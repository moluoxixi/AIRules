# O-01 · 回路熔断缺少运行时承载（P0）

## 现状（核验通过）

`max_loop`（默认 3）与 `mismatch_loop`（默认 2）当前仅以**声明式文档**形式存在于 `rules/AGENTS.md` 核心门禁第 9 条，没有任何**运行时承载机制**。

核验证据（独立子代理逐字读取）：

- `rules/AGENTS.md:104` 仅声明式描述，`:61` 的 `loop_iteration` 是"按需附带、非每阶段强制"的可观测字段，**无机制**。
- `__test__/workflow-contract.test.ts:282-296`：5 条断言全是 `rules/AGENTS.md` **字符串文本存在性匹配**，无任何模拟回路执行或拒绝派发的行为断言。
- `scripts/` 全目录 Grep `loop|guard|iteration|max_loop`：仅命中测试 fixture 名，**不存在 loop-guard 实现**。
- `skills/subagent-driven-development/SKILL.md:118-124`：账本只记 task 级完成态与可选 `blocked_id`，**未记内层回路迭代计数**；`:91` 反向佐证主编排层无运行时计数承载。

## 为什么是结构性问题

1. **自我冲突**：`rules/AGENTS.md` "memory 读取与冲突优先级"段明确写道"memory 只是 context、不是 enforcement——强制约束须进规则资产（⑤），不能只写 memory"。但 `max_loop` 这种**必须强制**的约束目前等同于 memory（被主代理读取的背景上下文），未进入机制层。
2. **可观测性缺失**：`agents/debugger.md:40` 只是文字提醒 debugger "不自行决定回路是否继续"，仍把责任口头交给主代理，未给出机制承载点。
3. **熔断条件不可验证**：现有合约测试只能保证规则文本不丢失，不能验证"达到 `max_loop` 时主代理真的会拒绝再次派发 coder"。

## 学术对照（简）

LangGraph 在 state 中显式持久化 `iteration_count` 按字段路由；AutoGen `budget_manager` 是独立 runtime 组件；OpenAI Agents SDK guardrails 在代码层 hook 拦截。通用模式都是机制承载，而非 prompt 自觉。

## 修复建议

### Step 1 · 规则文档自我修订（轻量）

在 `rules/AGENTS.md` 第 9 条末尾增加一句明确执行责任主体：

> 回路计数 `loop_iteration` 由主代理（编排者）在每次跨阶段派发前后维护；reviewer / coder 子代理在 stage_evidence 中只**报告**当前回路标识与建议增量，**不**承担计数器的持久化。主代理在派发 coder 前 MUST 读取计数器，达到 `max_loop` 立即转 BLOCKED，不再发起新派发。

### Step 2 · 机制层承载（关键）

- 在 `skills/subagent-driven-development/SKILL.md` 进度账本段（当前 `:117-124`）增加"内层回路计数账本"子节，规定主代理在账本中维护 `{loop_name, iteration}` 键值对。
- 可选：新增 `scripts/lib/loop-guard.ts` 或 hook 层兜底——当主代理在长上下文中"失忆"时，由工具调用层硬拒绝超限派发，强制返回 BLOCKED 模板。
- 同步 baseline：`c:/users/administrator/.qoderwork/agents.md` 与 `rules/AGENTS.md` 保持一致。

## 回归测试设计（必须落地）

```yaml
TC-Loop-Runtime-001 (max_loop 失忆兜底):
  given: 主代理在 max_loop 后再次尝试派发 coder
  when: 派发请求进入编排层 hook / loop-guard
  then: 拒绝派发，返回 BLOCKED 模板

TC-Loop-Runtime-002 (三条内层回路独立计数):
  given: Consist→Code 已迭代 2 次 + Test→Debug→Code 已迭代 2 次
  when: 任一回路再迭代 1 次
  then: 两条回路独立达到 3 触发各自 BLOCKED

TC-Loop-Runtime-003 (mismatch_loop 独立):
  given: code-reviewer 连续返回 requirement_mismatch
  when: 第 2 次 mismatch 触顶
  then: BLOCKED 且不消耗 code_quality 配额

TC-Loop-Runtime-004 (BLOCKED 输出含证据):
  then: 报告含每次迭代失败 AC / coder diff / reviewer 反馈摘要
```

**红测验证**：机制落地前用"模拟 reviewer 始终 FAIL"stub 跑 TC-001，确认当前主代理无限派发（红）；机制落地后转绿。
