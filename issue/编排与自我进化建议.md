## 待修复项

### 1. `skills/writing-plans/SKILL.md` — "选填"措辞歧义

**问题**：第 30 行 `每个实现任务必须写明（按触及的栈选填）：` 中"必须+选填"并列，LLM 执行时将"选填"理解为"全部可选"，导致前端任务漏写 `**调用接口**` 字段。

**修复**：

```diff
- 每个实现任务必须写明（按触及的栈选填）：
+ 每个实现任务必须写明以下字段——依据任务触及的栈，该栈标注的字段为必填，未标注栈的字段可省略：
```

### 2. `rules/AGENTS.md` 阶段契约表 — 实现阶段缺"环境就绪"前置依赖

**问题**：阶段契约表中"实现"阶段的前置依赖只写了"实现计划与验收用例清单已就绪"。当目标栈的构建工具不存在时（如项目是 TS 但任务要求 Java），coder 被派发后才发现无法运行测试，浪费一轮子代理上下文。

**修复**：在阶段契约表"实现"行的"前置依赖"列追加：

```diff
  | 实现 | `test-driven-development` + ... | 实现计划、验收用例清单 | 源码 + 配套测试 |
+ 补充前置依赖：目标栈构建工具可执行（主代理派发前验证 build tool 存在且可运行基础命令；验证失败标 MISSING blocked，不派发 coder）
```

---

### 3. `agents/consistency-reviewer.md` — 回执缺 scope_hint 导致回灌无增量约束

**问题**：consistency-reviewer 判"不符"回灌 coder 时，只给了整体 FAIL + reroute_target: Code，未标明具体哪些 AC-id 不符。coder 收到后可能全量重写，引入新偏差，加速触达熔断上限。

**修复**：在 `agents/consistency-reviewer.md` 的"写入边界与输出"段追加回执字段要求：

```markdown
- 判 FAIL 时回执 MUST 包含 `scope_hint`：
  - `not_covered`: [AC-id 列表]
  - `partial`: [AC-id 列表]
  - `summary`: 一句话说明缺口
```

同时在 `rules/AGENTS.md` 的 Consist→Code 回路描述中追加：

```markdown
主代理回灌 coder 时 MUST 附带 consistency-reviewer 回执的 scope_hint，coder 仅针对 not_covered/partial 项做增量修改，不重写已 COVERED 的部分。
```

---

### 4. `rules/AGENTS.md` mermaid 流程图 — 缺 Recall 节点

**问题**：核心门禁 #8 明确要求"任务起始读回记忆"，但 mermaid 主流程图中 Intake 后直接到 Gate，无 Recall 节点。对自动化编排实现或新手读图者，缺图中节点等于不存在。

**修复**：在 mermaid 图中 Intake 与 Gate 之间插入：

```mermaid
Intake["任务进入"] --> Recall["recall-memory（有 .airules/memory/ 时）"]
Recall --> Gate{"需要规格契约?"}
```

### 5. `skills/brainstorming/SKILL.md` — 输出缺结构化就绪标记（可选改进）

**问题**：brainstorming 产出"需求事实源"后，下游 planner 只能逐段人工判断"关键事实是否非 MISSING"，无法机械校验。对自动化编排（如 hook 判定是否可进入 Plan）不友好。

**修复建议**（非强制，视是否需要自动化判定而定）：在输出边界段追加：

```markdown
需求事实源产出时，尾部附状态标记供下游机械判定：

- `## 状态：ready` — 关键事实已全部确认，可进入计划
- `## 状态：blocked` — 仍有未闭环澄清项（列表附后）
```

## 已验证无需修改的部分
