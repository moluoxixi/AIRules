## O-04 · 流水线执行缺少聚合 trace 格式

### 现状（核验通过）

- `rules/AGENTS.md` 阶段证据 schema 段只定义**每阶段独立**的字段清单（散文式说明），无 JSON/YAML 结构化 schema，也无跨阶段聚合容器。`loop_iteration`/`mismatch_loop`/`escalation_type`/`blocked_id`/`budget_hint` 仍按阶段附带，未给出聚合 trace 形态。
- `skills/session-capture/SKILL.md:22-44` 产出形式为 Markdown 模板（`# Session — <主题>` / `## 关键决策` / `## 踩坑与教训` / `## 可复用约定 / 模式` / `## 关联产物`），仅打 `[procedural]` / `[declarative]` 标签，**非结构化执行轨迹**。
- 跨 `skills/` 与 `rules/AGENTS.md` Grep `trace|pipeline.*schema|execution.*schema|aggregated|聚合` 仅命中 `skills/test-design/SKILL.md:46,50` 的 `traces_to`（测试用例→需求来源的反查字段），**与流水线执行聚合 trace 无关**。
- 跨阶段聚合事实上仅由 `subagent-driven-development` 的进度账本（`SKILL.md:117-124`）以 Markdown 行级形式承担（`Task N: complete (...)` 与 `BLOCKED <id>: ...`），仍非结构化聚合 schema。

### 为什么暂缓

- 不影响当前正确性，只影响后续 self-evolution 数据质量。
- 当前 `distill-candidates` 用启发式扫描 sessions/changes 已能产出可用候选，结构化 trace 是优化项不是阻塞项。
- 引入聚合 schema 需要把账本格式与子代理回执格式一并升级，工作量与 O-01/O-02/O-03 同级——但收益（self-evolution 数据质量）属"锦上添花"而非"修补漏洞"，优先级排在三者之后。

### 触发条件

任一发生时再启动设计：

1. `distill-candidates` 报告"启发式扫描信噪比下降"，需结构化 trace 提升提炼精度
2. 用户/团队提出按流水线粒度做指标分析（如"过去 30 天 Consist→Code 平均迭代数"）
3. O-01 落地后发现账本格式已自然演化出 run-level 聚合需求

### 备选方向（不在本期落地）

按轻→重：run-level YAML 时序追加 → JSONL + 离线聚合 → 完整 trace store（OpenTelemetry / Letta-style）。

## E-02 · 纵向评测依赖宿主 runtime（自我进化 Gap 3）

### 现状（核验通过 — 显式取舍而非疏漏）

`skills/distill-candidates/SKILL.md:36-45`"库级健康复核"段列出 4 类信号：长期不被触发 / 触发但屡被覆盖/绕过 / 记忆已 superseded 或事实失效 / 重复或碎片。

但同文件 `:45` **明确否定** runtime 计数器方案：

> AIRules 是纯 prompt 项目、无运行时自增计数器，上述信号靠**扫描沉淀素材的启发式判断**得出，不要求每条 skill/记忆维护精确的 `recall_count`/`override_count` 字段（那是无客观信号的重型治理，违背 baseline 取舍原则）。

跨 `skills/` Grep `recall_count|override_count|retrieval_frequency|trigger_count`：仅命中上述这一处**反向声明**，无任何 skill 定义过 runtime 事件流契约或消费过此类字段。

### 性质判定与启动条件

这是**显式取舍**：项目主动选择放弃 runtime 信号、采用启发式扫描沉淀素材作为唯一来源。按"功能完备性"是 Gap（无法精确量化 skill 退化），按"baseline 取舍"不是 Gap（自觉避免无客观信号的重型治理）。

只在宿主 runtime（QoderWork / Claude Code / Cursor 等）提供 recall 事件 + override 事件 + 事件聚合查询三类能力后才有意义启动。AIRules 仓库定义"信号判据"（如 override_rate > 70% → suspect）；宿主提供事件流 API；`distill-candidates` 在 runtime 可用时消费事件流，否则降级到当前启发式。
