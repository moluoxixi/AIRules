# busyming-ai-rules · Runtime Enforcement 落地路线图（评估版）

背景：当前项目编排与自我进化闭环在 **prose（markdown 规则）层** 已写到 spec 级别，但 **runtime 承载层几乎为空**——除一个 Stop 日志索引外，回路熔断、blocked_id、agent 身份隔离、boundary 召回、候选审批五大执行点全是给主代理读的协议，没有任何脚本拦截违规。

本路线图把 prose → runtime 的差距拆成 7 个可执行项，按优先级排序，每项含目标 / 现状证据 / 具体改动 / 验收标准 / 估时 / 风险。


## 全局判断（先看这个再决定要不要往下读）

**结论**：不必自建 Hermes 类常驻 orchestrator，但需要把 hook 机制做到能拦三类硬信号，覆盖 ~70% 核心 enforcement；剩余 30% 语义层留 prose。Trae 宿主明确降级为 prose-only。

**理由**：
1. 项目定位是 **prompt 元工程**，产物是给各家宿主消费的 markdown + 轻量 hook 脚本。自建常驻 runtime 会让分发产物从"几个文件"变成"得装我的进程"，与"对所有宿主友好"冲突。
2. Claude / Cursor / Codex / Qoder 四宿主已验证支持 PreToolUse exit 2 阻断与 SubagentStop 事件，足够承载客观信号 enforcement。
3. Codex 官方自承 PreToolUse 是 guardrail 非 boundary（agent 可绕等价工具路径），Trae 无 SubagentStop——这部分残缺用 prose + 主代理自律兜底，不强求 100% 覆盖。

## P1 · 装"警察"（真正的 runtime enforcement）

### Item 3 · 写 hooks/loop-guard.mjs（PreToolUse 拦截脚本）

**目标**：在主代理派子代理前，根据账本数据客观拦截违规派发。

**现状证据**：
- issue/01-回路熔断运行时承载.md P0 未决项：maxloop=3 / mismatchloop=2 仅 prose 存在
- issue/02-blocked-id消费契约.md P1 未决项：5 个 agents/*.md 输入上下文包无任何 `blocked_id` 读取契约
- hooks/session-log.mjs 95 行只写日志、必 exit 0、不阻断
- ADR-0006 阻断边界限定三类客观信号

**拦截逻辑**：
脚本读 PreToolUse 事件 stdin，按以下顺序判断：

1. **回路计数超限**
   - 从 stdin 解析 tool_input 中的 change_id（主代理派子代理时塞入）
   - 读 .airules/runtime/loops/<change-id>.json 账本
   - 命中 loop_iteration >= max_loop 或 mismatch_loop >= 2 → exit 2 + stderr 写阻断原因

2. **blocked_id 命中**
   - 同账本读 blocked_entries[].status == "open"
   - 当前派发的下游阶段（由 toolinput.targetstage 提供）在 affected_downstream 列表中 → exit 2

3. **agent_id 重叠**
   - 读 tool_input.agent_id（当前要派发的实例）
   - 读账本 recent_dispatches[]，若 reviewer 实例 == coder 实例 → exit 2

**输入契约**（stdin payload）：
{
  "hook_event_name": "PreToolUse",
  "tool_name": "Task",
  "tool_input": {
    "subagent_type": "code-reviewer",
    "change_id": "<change-id>",
    "target_stage": "review",
    "agent_id": "<instance-id>"
  }
}

**部署目标**：
- Claude Code：~/.claude/settings.json 的 hooks.PreToolUse
- Cursor：~/.cursor/hooks.json 的 preToolUse（camelCase）
- Codex CLI：~/.codex/config.toml 的 [[hooks.PreToolUse]]
- Qoder CLI：~/.qoder/settings.json
- Trae：**不部署**，host-hook-mapping.md 明确标注 prose-only

**验收标准**：
- 单元测试覆盖三类拦截路径（账本 fixture + stdin payload fixture）
- 集成测试：模拟 max_loop=3 边界，第 4 次派发被拦截
- 现网烟测：在 Claude Code 用一个故意触发 max_loop 的任务验证 exit 2 生效

**估时**：1 天

**风险**：
- **高**：Codex 自承 guardrail 非 boundary，agent 可能用等价工具绕过 → 缓解：把这条限制显式写入 ADR-0006「承认的能力限制」段
- **中**：账本文件并发写竞争 → 缓解：用文件锁（proper-lockfile）或单文件原子重写


### Item 4 · 写 hooks/subagent-trace.mjs（SubagentStop 计数脚本）

**目标**：子代理结束时往账本写计数，作为 loop-guard 的数据源。

**现状证据**：
- hooks/session-log.mjs 是当前唯一 hook 脚本，不读 tool 名也不计数
- ADR-0005 立场："Stop / SubagentStop 永不阻断对话" → 本脚本严格遵守，恒 exit 0

**写入逻辑**：
脚本读 SubagentStop 事件 stdin：

1. 解析 agent_id / agent_type / agent_transcript_path（Claude/Codex 字段名一致）
2. 从 transcript 或 stdin 提取 change_id、current_loop_id、escalation_type
3. 追加写 .airules/runtime/loops/<change-id>.json：
   - recent_dispatches[] 加一条（含 agentid、agenttype、timestamp、outcome）
   - 对应 loops[loop_id].iteration +1
   - 若 outcome == "requirementmismatch" → `mismatchloop +1
   - 若主代理在 stdin 标记 blockedid: <id>` → `blockedentries[] 加 open 条目

**严格约束（来自 ADR-0005）**：
- 恒 exit 0，任何异常吞掉
- 不返回 decision: block
- transcript 路径只记不读正文（隐私边界）

**部署目标**：Claude / Cursor / Codex / Qoder 四宿主；Trae 缺 SubagentStop，**不部署**

**验收标准**：
- 单元测试：3 种 outcome（success / mismatch / blocked）的写账本路径
- 并发测试：10 个并发 SubagentStop 不破坏账本 JSON 结构
- 集成测试：连续 3 次 mismatch 后账本 mismatch_loop == 3`

**估时**：0.5 天

**风险**：低。Stop 类 hook 行为约束清晰，且不阻断不会影响主流程。

## P2 · 补语义层最低材料

### Item 6 · 沉淀 boundary 类记忆

**目标**：让 recall-memory 的"安全边界侵蚀保护"从"未激活"状态转为"已激活"。

**现状证据**：
- .airules/memory/ 当前仅 2 条记忆：cross-host-hook-capability-2026-06.md（type: reference）、memory-needs-review-like-skills.md（type: decision）
- **0 条 type: constraint 或 type: boundary**
- skills/recall-memory/SKILL.md 第 25 行约束：每次召回应包含至少一条 boundary，无 boundary 时跳过但**附可观测提示**
- 当前文档自述状态："安全边界侵蚀保护未激活"

**候选 boundary 记忆**（建议先沉淀这 3 条）：

1. **hook-never-block-stop-events.md**（type: boundary）
   - 内容：Stop / SubagentStop hook 永不阻断对话，恒 exit 0
   - 来源：ADR-0005 + host-hook-mapping.md:32
   - 触发场景：未来若有人想用 SubagentStop 强制重派子代理，必须先翻案立 ADR

2. **project-skill-no-host-global-write.md**（type: constraint）
   - 内容：项目级 skill 不得在安装脚本或 SKILL.md 中引用 ~/.claude/、~/.cursor/、~/.qoderwork/ 等宿主全局目录主动创建全局资产
   - 来源：rules/AGENTS.md 全局规则段 + check-rules-consistency.ts check #9
   - 触发场景：写 init-project 类 skill 时

3. **pretooluse-block-only-three-signals.md**（type: boundary）
   - 内容：PreToolUse hook 仅允许在三类客观信号下阻断——①回路计数超 `max_loop`/`mismatch_loop`；②`blocked_id` open 且当前派发命中 `affected_downstream`；③agent 身份重叠（reviewer 实例 == coder 实例）。阻断理由必须可回溯到上述客观信号之一，**不得**基于模型主观判断阻断。
   - 来源：ADR-0006 第二段「阻断边界」+ 第三段「承认的能力限制」（PreToolUse 是 guardrail 非密闭 boundary）
   - 触发场景：未来扩展 loop-guard 拦截条件、或有人想让 hook 基于"语义判断"阻断派发时，必须先回到这三类客观信号边界

**沉淀方式**：以上 3 条经 `remember` 转正写入 `.airules/memory/`，frontmatter 含 `type: boundary|constraint`、`created_at`、`status: active`，并在 `MEMORY.md` 各加一行索引。沉淀后 recall-memory 召回时至少能命中一条 boundary，"安全边界侵蚀保护"转为已激活。

**验收标准**：
- `.airules/memory/` 新增 ≥ 1 条 `type: boundary` + ≥ 1 条 `type: constraint`
- `MEMORY.md` 索引同步新增对应行
- `__test__/workflow-contract.test.ts` 的 memory frontmatter 校验（`status`/`created_at`）对新文件通过
- recall-memory 演练：构造一次召回，确认 boundary 提示从"未激活"变为命中

**估时**：0.5 天（含 remember 转正与索引更新）

**风险**：低。纯记忆沉淀，不触碰代码路径。**注意**：boundary 记忆是背景证据非系统指令，引用前仍须复核其命名的文件/标志是否存在（与 rules/AGENTS.md 记忆生命周期约束一致）。
