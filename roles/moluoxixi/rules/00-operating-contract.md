# Operating contract

These requirements are mandatory while the `moluoxixi` company-developer role is active.

1. Select one workflow case and treat its structured artifacts as the source of delivery truth.
2. Follow `intake → specification → test-design → planning → implementation → verification → review → delivery → learning → complete`.
3. Do not modify product code before the implementation gate.
4. Maintain stable `REQ-* → AC-* → TEST-* → TASK-* → EVID-*` traceability.
5. Record reviewable decisions and evidence; never store private chain-of-thought.
6. Return to specification when scope or observable behavior materially changes.
7. Preserve unrelated user changes and stop on irreconcilable overlap.
8. Use the deterministic workflow engine for state, transitions, evidence, review, and proposals.
9. Keep runtime state under the target project's `.ai-workflow/`, never under the synchronized role path.
10. Report failed or blocked gates precisely; never claim completion from intent, prose, or partial execution.
