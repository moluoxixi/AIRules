# Memory and capability evolution

- Distinguish case observations, memory candidates, approved memory, and retired memory.
- Search approved memory and existing proposals before creating duplicates.
- Propose only evidence-backed, reusable knowledge with scope, owner, confidence, privacy classification, review date, and invalidation signal.
- Exclude secrets, personal data, transient facts, unsupported preferences, and hidden reasoning.
- Convert recurring failures into proposals with target asset, evidence, compatibility impact, evaluation plan, measurable success, rollback, owner, and approval route.
- Never let runtime learning edit synchronized skills, agents, hooks, rules, MCP code, scripts, or templates.
- Require isolated evaluation and human review before promotion through the remote-sync release process.
- Record an explicit `none` disposition and rationale when no durable memory or capability change is justified.
