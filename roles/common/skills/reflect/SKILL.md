# Reflect（反思归因）

产物不符合预期或规范时，先找清楚**错在谁负责的那一层**，再给出证据、修复点，以及这个教训以后该沉淀到哪里。它不只是修当前文件，而是回答"为什么会写成这样"，让对应的 skill、规则或执行方式被修正。

## 触发条件

- 用户说"这文档/产物不符合规范 / 为什么会这样 / 复盘一下 / reflect"，或对已交付产物表达不满、要求追因时按名调用。

## 不适合场景

- 单点笔误、已明确定位的小 bug → 直接修，不必走归因流程。
- 产物其实符合规范、只是用户偏好不同 → 那是需求澄清，不是根因归因。
- 证据不足以支撑归因（看不到产物、看不到所依据的 skill/规则、不知道用户的"规范"具体指什么）→ 标 `MISSING` 并先索取证据，不臆造根因。

## 归因维度

先分清两个问题，不要混在一起：

1. **问题属于哪一层资产**：这决定应该修哪一类文件。
2. **教训以后放在哪里**：这决定是写记忆、提 skill 候选，还是改规则资产。

资产层级用中文判断：

- **仓库维护层**：AIRules 仓库自己的根 `AGENTS.md`、`CLAUDE.md`、脚本、测试、README 等维护资产。
- **角色资产层**：`roles/common/`、`roles/development/`、`roles/product/` 下面会被分发的 skill、hook、规则和配置。
- **项目初始化层**：`init-project` 注入到用户项目的模板、脚本、参考文件。
- **项目生成层**：已经生成到用户项目里的 `AGENTS.md`、`knowledge/`、`openspec/` 等产物。

教训落点单独判断：

- 是"以后遇到什么场景该怎么做" → 提炼成 skill 候选。
- 是"这个项目里的事实、约定、踩坑" → 写项目记忆。
- 是"用户跨项目偏好或通用习惯" → 交宿主的全局记忆承载。
- 是必须强制执行的约束 → 改规则资产，不只写记忆。

| 根因类别 | 判据 | 典型证据 |
|---|---|---|
| **skill 缺陷** | 照着 skill 做也会错：触发条件、禁用场景或流程写得含糊、缺失或自相矛盾 | 指出 skill 文件里那段含糊或缺失的指令 |
| **规则缺陷** | 角色规则、初始化规则或用户项目规则与期望冲突，或没覆盖该场景 | 指出规则/配置/注入参考文件里冲突或缺失的条款 |
| **执行偏移** | skill 和规则都正确，但执行时偏离了它们：没按流程走、漏了门禁、把示例当真实事实 | 对比"规则要求"与"实际产物"的偏差点 |
| **输入缺陷** | 根因在上游——需求/PRD 本身 `MISSING` 或歧义，规则资产无责 | 指出输入里缺失或多义的关键事实 |
| **安全边界被经验盖住** | skill 和规则都正确，但召回的"怎么做"经验压过了"何时不要做/必须先确认"的边界 | 指出哪条记忆压过了边界，或边界类记忆缺失/召回不足 |

## 流程

1. 收集证据：被认定有问题的产物、用户的具体不满点（"不符合规范"指哪条规范）、产出该产物时所依据的 skill / 规则。
2. 判定资产层级：产物属于仓库维护层、角色资产层、项目初始化层、项目生成层中的哪一层，归因只在该层及其依据的规则资产内进行。
3. 逐维度核对上表判据，命中即记录证据；证据不足的维度标 `MISSING`，不强行归类。
4. 输出归因报告 + 修复点 + 教训路由（见下）。

## 输出

```markdown
## 反思归因 — <产物/问题简述>

### 资产层级
<仓库维护层 / 角色资产层 / 项目初始化层 / 项目生成层 之一>

### 根因
- [skill 缺陷 | 规则缺陷 | 执行偏移 | 输入缺陷 | 安全边界被经验盖住]：<结论> — 证据：<指向具体文件:行 或 流程节点>
  （可多条；无命中的维度标 N/A，证据不足标 MISSING）

### 建议修复点
- <指向具体 skill/规则文件或流程节点的可执行修复>

### 可复用教训
- <若有跨任务复用价值的事实/教训 → 路由 remember（用户当场确认即写）或 distill-candidates（提炼成记忆候选待审）落 `knowledge/memory/`；
   若是"遇到什么场景该怎么做"的做法 → 路由 distill-candidates 提炼 skill 候选待审；
   一次性偶发 → 不沉淀>
```

## 纪律

- 只诊断、不臆造：每条归因必须有证据；证据不足标 `MISSING`，不猜根因。
- 不跨层归因：项目生成层的问题不归咎于仓库维护层规则，反之亦然。
- 状态仍用 `PASS` / `FAIL` / `MISSING` / `NOT RUN` / `N/A`，但输出时要写清中文原因，不把"没查到"写成"没问题"。
- 教训只路由不直接固化：本 skill 不自行写记忆或 skill 候选，由 `remember`（显式即写）/ `distill-candidates`（提炼候选待审）落盘（保持单一职责与写入边界）。
