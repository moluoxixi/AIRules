# Scenario acceptance

- Business pages: close product requirements and confirm API fields support each function. Use accessible design files as authority; use prototypes only when no design exists. Inspect the actual running page using the project's mandated portal/local integration entry.
- DIY products: clarify critical user flows, states and architecture constraints. Without a design, provide a visual proposal users can assess. Verify a representative complete business flow.
- npm/CLI: review public APIs, types, error semantics and compatibility. In declared supported environments test the packed artifact through the consumer installation/import/command path.
