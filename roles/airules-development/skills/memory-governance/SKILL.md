# Govern memory and promotion

Keep five layers separate:

1. Run context: temporary prompt and tool output with a TTL.
2. Change memory: decisions, failure signatures, evidence, and handoff scoped to one change.
3. Candidates: untrusted reusable claims with provenance and scope.
4. Approved memory: reviewed facts with version, expiry, and conflict rules.
5. Policy assets: evaluated skills, rules, hooks, agents, and schemas.

For every candidate record source evidence, scope, trigger, claim, confidence, conflicts, sensitivity, expiry, destination, eval cases, and rollback condition. Remove secrets, personal data, transient paths, and unsupported conclusions.

Promote only after deduplication, conflict checks, positive and negative evals, and required review. Prefer memory over a rule, a skill over a hook, and a scoped project asset over a global asset when the stronger form is not justified.

Raw transcripts and single-run guesses must never enter approved memory automatically.
