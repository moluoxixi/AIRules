# 0.13.0 设计与现状审查

审查基线：`ba53138`（0.12.1）。目标是让日常开发顺手、上下文可接续、交付可复核，复杂性可以在执行中重新判断。GPT-6.2、Fable 在此表达设计方向；本次没有以模型名称推断能力或建立兼容等级。

## 从哪里产生负担

旧版 `new --light` 仍在 `runtime/sync.py` 的 `save_cards` 为故事/场景生成开发与验证动作，`capture` 自动写入 `finish`。技能要求每项行为变更都建需求、建卡、登记实现、采证。表面省掉领取，内部仍维护整个动作状态机；从“轻量”切换到编排又带来第二条路径。

旧 `runtime/evidence.py` 的 `run` 接受退出 0、有输出且未识别出失败摘要的命令；`print('ok')` 也可成为通过凭据。签名和输入绑定保证记录的一致性，却不证明断言覆盖业务目标。`ready_to_deliver` 把内部记录齐备与业务交付联系得过紧。

旧 `runtime/knowledge.py` 的 `card_input`、`source_result` 要求故事、场景、动作及有效通过回执。它保存了任务经验，难以自然表达尚未实测的现行政策、跨功能状态流转或术语。项目首页是任务卡列表，不能直接回答业务现在如何运作。可选 `.requirements/rules/index.md` 指针没有形成业务现状及生效范围的维护语义。

把“纯重构”“依赖升级”整体排除也有遗漏风险：这些修改可能触及鉴权、序列化或共享运行时行为。复杂性需要在调查、实现和交付时持续重估，不能由最初任务标签永久决定。

上述位置均可在基线提交中复查；旧源码及测试不留在新版发行资产中作为备用实现。

## 保留、改造与移除

| 能力 | 决定 | 原因与新落点 |
| --- | --- | --- |
| 用户预期、实现、实际结果分别说明 | 保留 | 技能与工作记录中的核心交付语义 |
| 场景对应实际证据；失败与未测不算通过 | 保留 | 执行者对照断言和观察，明确覆盖及限制 |
| 代码/预期改变后判断须复验范围 | 保留并缩小工具责任 | 持续影响判断；可选工具复核显式文件范围，不推断外部环境 |
| 收窄承诺需保留实际决定 | 保留 | 原目标和延期/撤出依据留在变更记录，不作通过计数 |
| 每项行为变更先创建故事与动作 | 移除 | 简单任务直接做；持续上下文才保存短记录 |
| 五专项技能路由 | 合并 | 单入口加三份按需参考，减少同义指令及流程跳转 |
| DAG、领取/署名/动作完成状态 | 移除 | 宿主和实际协作管理执行；普通记录承载分工与交接 |
| 相同失败两次强制独立执行者 | 改造 | 无信息增量时换诊断方法，按影响选择第二视角 |
| HMAC、密钥跨工作树迁移 | 移除 | 本地记录不可证明业务真实性；保留内容摘要检测意外变化并公开能力边界 |
| 图页及本地服务、离线模型投影 | 移除 | 业务叙述/表格/必要简图直接在项目文档阅读，无双表示同步维护 |
| 经验提案/批准/采用/退役与索引 | 移除 | 业务知识是独立现状，重要经验直接落到相关规则、实现或断言 |
| 项目安装器、历史格式升级、旧模型兼容模式 | 移除 | Beta 无兼容义务；公共技能投影已足够，不复制运行时到每个项目 |
| 更显式的步骤或分工 | 可选文字约定 | 实际需要时在同一工作记录中表达，不维护第二套引擎 |

## 新的责任边界

技能负责决策提醒：按影响调查、动态补约束、选择有意义的验证、保留必要上下文。它不能机械强迫一个模型诚实或理解业务；可复核的来源和反例演练比“完成”开关更接近这个目标。

业务说明负责当前理解，能独立于某项任务阅读；变更记录负责差异与决定；验证记录负责特定条件下的实际观察。三种含义可以链接或出现在同一页的明确栏目中，无需规定三个文件。项目已有导航和文档位置优先，fallback 只是没有约定时的选择。

工具仅负责重复、可确定的工作：采集命令结果、保存日志、摘要显式输入，随后检查它们是否变化。它不自动判通过，不管理验收状态，不推断未列出的共享依赖、断言或外部系统。输出可随项目保存，也不提供恶意篡改防护。人工和真实环境证据由执行者记录部署、入口、数据条件与观察。

公共 AIRules 分发层保留，角色只投影一个技能。没有修改项目 AGENTS 的安装副作用，也没有导入记忆/图形库等新运行依赖。

## 如何判断设计是否有效

自动测试只覆盖分发与工具的确定性契约。模型行为另用最少原始材料的独立演练观察：局部修改是否直接做，隐藏约束是否及时扩展，退出 0 的弱断言是否被识别，接手者能否区分当前政策、待生效目标与局部实测。原始场景在 `__test__/scenarios/`，结果及未验证项记录在 [VERIFICATION.md](VERIFICATION.md)。

不声称新旧方案的长期效率已经量化，也不声称跨模型一致性已经验证。若后续真实使用反复遗漏某种约束，先依据失败证据改触发提醒或验法；只有显式编排表现出可复现的净收益时再增加能力。
