## 工具实际证明的边界

黑盒回归实际执行了命令，验证 stdout/stderr、退出码与 cwd；`print('ok')` 和空输出都只得到执行成功事实，没有业务通过字段。非零退出及缺失程序留下失败记录，复核不重新执行命令。

输入范围内的未提交改动、目录新增/删除、多输入变动、日志修改/丢失和链接替换都会使原记录失效；运行中修改后还原也会被文件标记识别。证据输出自排除，既有回执和原始输出不覆盖。项目外路径、符号链接和空输入被拒绝。普通本地 Git 提交与新克隆交接后，回执和 `.output.txt` 仍可一起复核。

首轮反例发现 macOS `/var` 与 `/private/var` 别名使合法绝对路径误判越界，修复后回归通过。另针对常见 `*.log` 忽略规则采用 `.output.txt`，避免原始输出在普通交接时丢失。

这些检查不证明断言覆盖业务、输入列表完整、外部环境不变或记录不可伪造。历史“current”不等于当前业务已验收；技能要求执行者对这些语义再作判断。
