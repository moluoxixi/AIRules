# 接口契约核对

从具体故事或操作开始，读取接口说明、接口类型定义、真实调用点及允许访问的网络记录。写清环境和各来源位置，区分文档声明、代码采用的口径和实际观察。已有需求图用项目内 `flow.py task <需求ID> context <故事ID>` 读取现有契约。

1. 跟踪一次操作经过的页面入口、实际方法和路径、请求构造、响应业务状态、处理分支、回显。记录真正使用的接口；同一字段在 UI 和传输层名称不同时写出映射。
2. 逐项核对这条链路依赖的字段。记录路径、类型、是否必填、空值、业务枚举或单位、来源、谁写谁读，以及对应页面结果。搜索和分页核对条件是否交给后端、总量口径和跨页范围。根据业务只检查相关项。
3. 将不一致写成可复核的问题。给出最小操作、预期与实际、哪个故事会受影响，以及需要的决定或上游支持。示例或 mock 只作为示例来源；缺少可靠来源、尚需确认的契约保留 `open`。
4. 已启用需求图时，在契约的 `endpoints` 中为每个 HTTP 方法和路径记一条。用途写业务动作，如“批量撤销确认”。沿调用点分别填写该接口的请求字段、响应字段和来源。补录旧契约时，仍待核对归属的字段保留在契约级 `fields`。结构和示例见[记录格式](../requirement-flow/references/model.md#按接口记录字段)。
5. 只有实际对齐的记录转为 `confirmed`。让消费该契约的动作引用其 ID，需要补研的动作可通过 `closes_contracts` 承担确认责任。交付时指出已核实的字段、仍缺的证据和具体受影响功能。

项目内 `flow.py` 位于 `.agents/skills/requirement-flow/`。独立核对可直接提交针对该操作的字段映射与问题清单。
