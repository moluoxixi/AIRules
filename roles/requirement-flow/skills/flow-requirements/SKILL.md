# 需求分析

先确定本次要回答的业务问题。读取用户原话、可用的原型或业务说明、已有故事与已确认的决定。项目已使用需求图时，用 `flow.py task <需求ID> context [故事ID]` 获取相关记录，`flow.py` 位于项目的 `.agents/skills/requirement-flow/`。独立调用时也可直接对用户给定的材料做评审。

1. 按用户能够独立承诺、验收和延期的结果拆故事，而非按页面、字段或代码文件数量切卡。同一结果的正常、失败和恢复场景保留在同一故事；共享开发可以复用，独立交付通常分别结束验证动作。为故事写角色、开始状态、触发操作、业务处理、结束状态与可见结果，附原文或原型位置。对现状、拟变更行为和待确认条件注明来源；拆合既有故事前按[范围与重组边界](../requirement-flow/references/model.md#缩小已确认的范围)检查原场景归属和恢复路径。
2. 从一条完整业务路径开始，顺着入口、判断、状态变化、反馈与后续操作逐步走通。逐项考虑与本功能有关的角色权限、边界值、空数据、重复操作、失败重试。例如“保存”需要说明保存失败时草稿去向、重试后的结果；无关边界可略过。
3. 给每条验收场景稳定 ID，用具体的前提、操作与可观察结果写 `given/when/then`。能从材料查明的问题先查；需要业务取舍时列明确切选项、各自影响及受影响故事，把无关故事留为可推进。
4. 轻量需求用 `cards` 回写故事和场景，验法需要交接时写 `checks`。其它需求用 `plan` 回写故事和动作，以 `covers` 对应场景。修改保留场景 ID；缩小已承诺的范围时，由实际决定人选定方案，再将故事变更与 `retire_scenarios` 一起登记。涉及未知字段转交 `flow-contracts`。向负责人展示故事清单、验收例子和仍需决定的问题。轻量字段见[轻量交付](../requirement-flow/references/lightweight.md)。

记录格式与可运行命令见[需求图字段说明](../requirement-flow/references/model.md)。独立评审交付相同结构的结论即可。
