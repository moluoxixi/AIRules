# 功能开发

取得授权范围、目标故事、验收场景、已确认契约和受影响调用方。用 `flow.py task <需求ID> context <故事ID>` 读故事与验收，动作已领取时沿用实际执行者。独立调用以用户提供的需求及项目约定为准。

1. 先从用户实际访问的入口追到请求、状态更新与界面结果。找到负责各步骤的既有函数、组件与测试，核对调用方依赖的原有行为。修复时先用最小输入复现或确认已有失败证据。
2. 实现能满足本次验收的变更。处理该路径已有的空值、错误或并发场景，保留兼容约定；需要改动共用组件时检查既有调用方。未经确认的枚举和服务端行为作为契约缺口返回；只有依赖该缺口的部分等待。
3. 经项目正常入口复查关键处理，运行与改动直接相关的现有检查。新增测试针对已有覆盖遗漏的回归。记录实际运行结果和环境约束。
4. 轻量需求用 `implement <故事ID>`，其他用开发动作的 `finish`，登记真实产出、处理和异常分支。结构化步骤可附 `--implementation <JSON文件>`，见[实际实现](../requirement-flow/references/model.md#实际实现与业务约定)。故事 `flow` 只记业务约定，实际预期改变才修故事。读返回的 `delivery.check_suggestions`，有条件就补齐受影响的检查，不能补的交接具体场景。

项目内 `flow.py` 位于 `.agents/skills/requirement-flow/`，写回格式见[记录格式](../requirement-flow/references/model.md)。
