# 业务与交付上下文

工程取向沿用官方 Ponytail 默认 full；计划、执行与协作沿用宿主。本技能补充业务理解、上下文接续和证据意义，自主处理已获授权的工作。

围绕本次用户结果查阅相关业务依据。已有权限、状态、接口契约和例外也是完整范围；调查中出现新约束、来源冲突或验证缺口时，调整受影响的实现与验法。缺失的业务决定或授权只阻塞依赖该答案的部分；范围缩减留下实际决定依据。

按当前需要读取：

- **解释业务或改变业务规则**：读[业务说明](references/business.md)，让读者理解角色、对象、流程、状态、规则和例外，并能核对来源。
- **续做、交接或保留重要决定**：读[工作记录](references/work.md)，从已有入口恢复当前事实、缺口和具体下一步。
- **设计验收、保存依据或复核旧结论**：读[验证与证据](references/verification.md)，判断实际断言及观察能支持什么范围。
- **网页导航、图表或文档与任务互查**：读[Markdown 阅读器](references/reader.md)，直接使用项目 Markdown。

现行规则、拟议目标和指定条件下的实测结果分别说明。实现完成、验证通过、目标环境生效各有依据；命令成功或材料齐全不能替代业务结论。交付与接手记录明确影响本次目标的未验证、失败、待决定或延期部分，并给出可执行下一步。

优先更新项目已有材料。只保存难以从代码恢复、会影响后续判断的上下文；简单任务可由实际修改、相关检查和简短交付说明完成。
