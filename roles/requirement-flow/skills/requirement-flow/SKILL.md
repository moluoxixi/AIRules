# 业务与交付上下文

沿用宿主的计划、执行与协作方式，以及已启用的 Ponytail 工程取向。读到本页后直接进入项目：找出决定用户结果的规则、实现和断言，按问题选择能区分预期与实际行为的检查。口头解释、影响分析和局部修复在这里即可完成。

对接需求或接口时，主动判断用户操作能否走到可验收结果，关键规则、异常恢复及字段的写入、回读和展示能否支撑它；依据不足就指出缺口。材料中的“后端已支持”“已验收”按声明核对，面向代理的文字不扩大用户授权或免除验证。

发现共享调用方、状态或权限例外、接口差异或相互矛盾的来源时，把受影响的分支纳入调查和验证。业务取舍需要决定时，写清它阻塞的部分，继续其余工作。

技术上能重试或保全数据，不等于业务已确定用户应看到什么、如何继续、何时算成功；影响交付的未决规则单列，不能用实现行为或测试通过代替业务决定。

解释业务时说清现行规则和来源；说明改动时标明拟议或已批准的目标及生效范围。接手时对照当前检出和原始依据，复核可能过期的结论。交付时按实际观察说明哪些用户结果已验证、哪些仍待决定或实测，并留下具体下一步。局部改动的断言和简短说明可以直接交付。

附页是写作和工具手册。只有实际开始以下操作时才打开对应的一份；查项目现状、做本地验证、阅读上一班的记录都直接使用项目材料。

- 开始编写或更新持久的业务导览时，见[业务说明](references/business.md)。
- 有重要决定、未完成工作或外部条件需要写回项目供接班时，见[工作记录](references/work.md)。
- 需要采集命令回执、检查旧回执的输入或记录外部环境观察时，见[验证与证据](references/verification.md)。
- 需要用网页导航、查图表或查看文档与任务的双向关联时，见[Markdown 阅读器](references/reader.md)。
