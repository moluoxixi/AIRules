# 工作记录：让下一位能继续

在续做、跨会话交接或保留难以从代码恢复的重要决定时读取。优先使用项目已有 issue、spec、PR 或任务文档；没有约定且确需仓库内记录时，用 `docs/changes/<有意义的名称>.md`。

## 留下影响下一步的信息

一份记录按需要回答：

- **目标与边界**：要改变什么、当前依据、仍须成立的业务约束，以及范围取舍的实际决定来源。
- **当前事实**：关键决定及理由、实际修改入口、所在分支或检出与相关未提交内容。
- **验证与缺口**：已观察到的结果和原始依据、适用条件，仍未验证、失败、待决定或延期的部分。
- **继续入口**：下一步可执行的命令或操作及输入条件；缺权限或数据时说明需要谁提供什么。

只保留后续执行者不能低成本从代码恢复的内容。小任务可以由已有提交/PR 说明承载。已有业务说明中的规则通过链接引用；工作记录承载本次差异与决定。

业务入口使用普通 Markdown 链接，例如 `[库存申请](../business/inventory.md)`；项目入口或相关业务页链接回记录。[阅读器](reader.md)可由这些链接计算反向关联，无需另一份任务状态。

## 接手与更新

接手时对照当前检出、diff、记录和相关来源，确认历史结论仍适用于现有代码、预期、环境与数据。保留原证据，失效部分标明需复验；已回答的问题按实际决定更新。

预期可以随决定调整，但原承诺被取消或延期时，保留决定来源、原因和影响。部分实现与部分验证分别说明。具体继续条件比“继续检查”更有用。

计划和协作由宿主安排。需要交接给其他执行者时，留下影响其工作的业务约束、输入版本、可写范围和预期证据；整合后的结论以实际组合结果为准。
