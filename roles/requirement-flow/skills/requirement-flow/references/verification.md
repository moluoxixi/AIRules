# 验证与证据

需要采集命令回执、检查旧回执的输入或记录外部环境观察时读取。按要证明的用户结果选择场景和断言，采证工具按需使用。

## 证据能证明什么

需求、接口和实现同时存在时，沿操作、请求、处理、响应及回读/可见结果核对。覆盖受影响的重要规则和例外；测试数量不代替这一判断。

| 证据 | 能支持的结论 | 仍不能据此声称 |
| --- | --- | --- |
| 保存命令退出 0 | 命令成功结束 | 数据已经持久化且重开正确 |
| 请求字段的单测断言 | 当前输入构造符合断言 | 服务端接受该字段、真实权限正确 |
| 测试库保存后重新查询 | 指定代码和数据下回读正确 | 生产部署已生效 |
| UAT 实际操作与回显附件 | 指定部署、角色和数据下观察到结果 | 其他环境和状态全部通过 |

记录预期、实际结果、检查/断言或观察附件，以及条件与缺口。没有覆盖关键命题的全绿结果仍不足以验收该命题。保留失败与未测记录，修复后的结果链接原问题。

过程结论也需要依据：报告“此前失败后修复”“由独立执行者接手”等过程时，要有对应输入、执行或交接材料。本次重放只证明本次结果，不能补证缺失的历史。

## 可选的命令采证

`scripts/evidence.py` 使用 Python 3.9+ 标准库，保存命令输出与显式输入摘要，并复核它们是否变化。它不判定业务通过或任务完成。

```bash
python3 <技能目录>/scripts/evidence.py run --project /path/to/project \
  --output docs/changes/evidence/save-01.json \
  --input src/inventory --input tests/test_inventory.py --input spec/inventory.md \
  -- python3 -B -m unittest tests.test_inventory -v

python3 <技能目录>/scripts/evidence.py check --project /path/to/project \
  docs/changes/evidence/save-01.json
```

- 命令在项目根执行，参数直接交给进程；复合命令需显式调用 shell。
- 每次运行使用新的回执文件名，同时保存 `.json` 和 `.json.output.txt`。交接时保留两者及声明的输入；工具按原始字节比对。
- 输入应覆盖影响断言的实现、共享依赖、测试、配置和需求/契约。目录输入包含文件增删和执行位变化；漏选输入不能由 `current` 补救。
- 输入输出使用项目内的实际路径；符号链接被拒绝。输出与输入分开，避免把依赖缓存、Git 元数据或本次证据当作业务输入。
- 参数、日志和附件使用可共享的脱敏内容；凭据、token、授权 URL 及私有数据留在其授权来源。

`run` 成功表示命令成功且采集期间所列输入未发现变化；失败仍保留记录。`check` 不重跑命令，其成功只表示成功执行记录的日志与所列输入当前一致。结合执行结果、输入有效性和实际断言判断。

工具能发现普通的执行期改动，但不锁定工作区、不推断传递依赖，也不提供防伪或外部环境保证。需要协调输入变动或更强隔离时，沿用项目与宿主的工作方式。

## 环境与接手复验

人工或外部环境观察记录入口、时间、部署版本、角色/数据条件、步骤、预期和实际结果及附件。截图只能证明可见内容，不能单独证明后台持久化或未展示的分支。

代码、预期、部署或数据改变后，重新判断哪些命题需要复验；历史提交名或代码摘要相同不能证明外部环境未变。将实现完成、验证通过、部署生效分别说明。证据不足的场景继续补足可执行部分；依赖外部条件的部分交接具体原因和下一步。
