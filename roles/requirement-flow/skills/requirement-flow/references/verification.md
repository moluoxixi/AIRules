# 验证与证据

在设计跨层验法、保存运行/人工证据或复核旧结果时读取。普通小修改直接运行合适检查，交付说明写出真实结果即可；不强制使用采证脚本。

## 先明确要证明的命题

以用户可观察的结果选择场景和断言，覆盖本次影响到的关键规则与例外。需求、接口和实现同时存在时，把操作→请求→处理→响应→回读/可见结果连起来。权限拒绝、状态边界、重复/并发、异常恢复等按实际风险选取，不用机械铺满测试矩阵。

| 所得证据 | 可支持的结论 | 仍不能据此声称 |
| --- | --- | --- |
| 保存命令退出 0 | 命令成功结束 | 数据已经持久化且重开正确 |
| 断言提交字段正确的单测 | 当前输入构造符合断言 | 服务端接受该字段、真实权限正确 |
| 测试库保存并重新查询 | 指定代码和数据下回读正确 | 生产部署已生效 |
| UAT 入口实际操作与回显附件 | 指定部署与操作条件下观察到结果 | 其他环境/状态全部通过 |

记录预期与实际结果，链接实际检查/断言、运行输出或观察附件，指出覆盖与缺口。全量测试通过但没有覆盖关键业务命题时，继续补有意义的验证，或明确该命题未测。失败输出与未测项保留；修复后新结果链接原问题，不能删除失败来制造全绿。

复核他人的验证材料时，最终代码、截图或测试快照只能支持其中可观察的结果。若要报告“此前失败后修复”“由独立执行者接手”等过程，还须有相应输入版本、实际运行或交接依据。历史依据缺失时，重放并记录本次结果，收窄原结论；本次重放不补证过去发生过什么。

## 按需保存命令证据

技能中的 `scripts/evidence.py` 使用 Python 3.9+ 标准库，不需安装依赖。需要跨会话保存日志、检查输入内容是否变化时可用；它不解析测试框架，不判定业务通过，不管理任务状态。

```bash
python3 <技能目录>/scripts/evidence.py run --project /path/to/project \
  --output docs/changes/evidence/save-01.json \
  --input src/inventory --input tests/test_inventory.py --input spec/inventory.md \
  -- python3 -B -m unittest tests.test_inventory -v

python3 <技能目录>/scripts/evidence.py check --project /path/to/project \
  docs/changes/evidence/save-01.json
```

命令在项目根执行，参数直接传给进程。复合命令需要显式调用 shell。每次运行选择新的回执文件名，上例同时保存 `save-01.json` 和 `save-01.json.output.txt`。Git 交接时一并提交这两个文件，核对两者均在提交中。复核比较原始字节，在会自动转换行尾的仓库，可用 `*.output.txt -text` 的 Git 属性保留附件原样。声明的输入也需要在接手检出中保留相同内容。

运行前确认命令参数与输出适合在项目中保存和交接。凭据、token、授权 URL 及私有数据不得进入参数或输出。需要脱敏的验证使用可安全共享的检查，或在人工记录中链接授权访问的原始依据。

显式输入必须覆盖会影响断言的实现、共享依赖、测试、配置以及需求/契约预期。可选择目录，目录内新增、删除及文件内容改变都会影响摘要；目录包含依赖缓存时应缩小到有意义的来源。本次输出目录应与输入分开，工具会排除本次回执和日志。它不会推断传递依赖、锁定工作区或覆盖外部系统；漏选输入不能由“current”补救。为避免读取到外部或遗漏链接目标，输入和输出路径中的符号链接均拒绝；子模块/嵌套仓库应选择实际需要的工作文件，避免把 `.git` 元数据当业务输入。

`run` 的 0 退出码仅表示命令成功结束且采集期间输入未发现变化；命令失败或期间发现变化返回非零，仍保存执行记录。`check` 的 0 仅表示该成功执行记录的日志与所列输入当前一致；失效、失败或记录错误返回非零。查看 JSON 中的执行结果、输入有效性及实际日志，再由执行者核对断言覆盖。摘要用于发现意外变化，可编辑文件不具备防伪能力，不能证明操作者、部署或业务语义。

工具比对运行前后的内容、文件身份与时间标记，能发现普通的改写后还原，但不持续监视或锁定文件系统，不能保证检测所有期间变化。检查期间协调其他写入者；需要更强隔离时使用项目允许的独立检出。原始证据作为交付物保留，临时脚本和数据按项目规则清理。

## 人工、外部环境与复验

人工观察记录操作入口、时间、部署版本、角色/数据前提、实际步骤、预期与实际结果、附件位置。附件应来自本次观察；截图证明可见内容，不能单独证明后台持久化或未展示的分支。外部系统版本与可用性需在使用时核实，遵循已有授权；缺权限只阻塞相应检查。

接手、改码、改预期、换部署或数据后重新判断证据适用性。选择性复验须能说明哪些断言受影响、哪些输入保持一致；相同提交名、历史任务状态或代码摘要相同都不能证明外部环境未变。将检查结论写回原记录，保留旧结果及其适用条件。

交付说明将已实现、已验证、未验证、失败、待决定/延期分别说清。已验证范围不足以支撑用户目标时，继续补足可执行部分；依赖外部条件的部分明确交接，不能用记录完整或脚本成功代替验收完成。
