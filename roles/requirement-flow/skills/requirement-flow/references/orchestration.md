# 动作编排

轻量需求用故事和场景 ID 直接交付，见[轻量交付](lightweight.md)。本页用于多人分工、契约确认、并行执行或独立复核：动作是领取、交接和写回的单位，字段见[记录格式](model.md)。

## 查看与领取

用 `task <ID> next --actor <执行者>` 查看待办、依赖与当前版次，用 `task <ID> context <故事ID>` 核对选定功能。返回动作的 `skill` 指明适用方法；结合用户授权和已有材料打开对应专项。编排需求在 `next` 返回 `review_skill` 时，先复核未覆盖的验收或交付问题；轻量需求完成后不再提示复核。计划中的动作可用 `skill` 指定更合适的方法。

专项可跳过、重复或组合。仅审查可止于问题清单；一张卡等业务决定时继续其他就绪工作。分派前查完整故事和 `covers`，因为故事筛选不缩减共享动作的范围。

## 写回

1. 用 `task <ID> claim --actor <执行者> --rev <版次>` 领取动作或继续自己的动作。轻量故事无需领取，`claim` 只领取后加的动作。换班时先用 `next` 核对持有人，再用 `task <ID> handoff <动作ID> --from <原执行者> --actor <接手人> --why '交接原因' --rev <版次>` 登记交接。
2. 补计划、故事、契约或依赖时用 `task <ID> plan <补丁.json> --why '依据' --actor <执行者> --rev <版次>`。业务选项由实际决定人确认后再用 `decision` 记入。遇到版次冲突，重读上下文和本次差异再写入。
3. 调研和开发的 `finish` 写实际产出及可复核位置。验证用 `verify-run` 执行检查，或用 `verify-observe` 登记真实观察，并核对场景覆盖。取得合格证据后用同一执行者和新版次 `finish` 验证动作；失败按受影响分支返工。命令、证据类型、场景 ID 和补丁字段见[记录格式](model.md)。
4. 失败时读 `verification_followups`，定位原因、按依赖返工并重测。同一场景、输入、命令和环境连续失败时，`claim` 安排 `flow-review` 诊断动作；原失败执行者不能领取它，交给实际独立的执行者领取，核对失败回执，并用 `finish` 记录结论和依据。其他就绪动作继续推进。诊断完成后再修复并采集新证据。有复用价值的结论用 `lesson-propose` 绑定原始回执，`lesson_reviews` 中的待审项交给另一位实际审查者。
5. 读 `finish` 返回的复验建议，再按 `delivery-check` 核对本期范围。用 `serve` 查看验收和依据，用 `archive <ID>` 归档已结束的需求。

## 子代理交接

同一需求同一时段只在一个检出里写需求记录（`model.json`），代码可按项目流程在不同 worktree 分工。换写入的检出前同步需求、证据并核对版次；共享签名密钥不提供跨树实时领取互斥。每位实际执行者使用稳定署名；独立审查由不同的真实执行者承担，更换署名不构成独立审查。

派发时交接需求、动作、故事和场景 ID、执行者、当前版次、授权范围、代码执行根、需求记录写入根、完整动作包及必要项目规则。失败诊断另交接可复现命令、数据和必要历史输入；私有材料按授权单独交接，公共摘要不要求公开原始日志。材料不足时返回待补事项。

修改进行中动作的输入前，先确认原执行者已停止且不再产生副作用；输入失效只撤销旧结果的有效性，不会终止真实进程。宿主不能中途通知运行中的子代理时，等它返回后再改输入。看到 `previous_execution` 时确认原执行已停止，再复核或领取。回包写完成、失败、取消或权限阻塞，产出位置、场景和回执 ID、最新版次及未覆盖项。版次或采集冲突须核对实际执行结果，再重读重采；拒收的结果不算已登记证据。

有子代理能力时可分派独立工作，由总入口汇总证据；单执行者可继续其他就绪工作，把独立审查留在队列中。跨层改动、重复失败或经验待审时，把原话、动作与场景 ID、回执和待判定的问题交给独立审查者。

## 项目经验

创建需求时先看原话命中的 `related_lessons`。拆出故事后，在 `next`、`context` 或 `claim` 里查看该故事的推荐和 `adopted_lessons`。打开原场景和回执，判断做法是否适用。决定采用时，用 `lesson-adopt` 把来源版本、目标故事和本次理由写回需求，再落实到实现或断言。已有采用记录可用于交接；退役经验只供追溯。命令见[经验的采用和退役](model.md#可在项目内复用的经验)。
