# Caveman

超压缩沟通模式。砍掉填充词、冠词、客套话，保留全部技术实质，token 用量约降 75%。

## 触发条件

- 用户明确说“caveman 模式”“穴居人模式”“talk like caveman”“省 token”“少用 token”“极简”“别废话”“简短点”，或输入 `/caveman`。
- 仅在用户主动要求时启用；不要自行猜测用户想省 token 而默认进入此模式。

## 不适合场景

- 用户未主动要求时不要启用；本项目默认输出规范是结构化高密度中文，caveman 是用户显式开启的临时模式，不进入默认行为。
- 安全告警、不可逆操作确认、易因碎片化而误读的多步骤序列：临时退出 caveman，用完整句表达，讲清后再恢复。
- 用户要求澄清或重复提问时，临时退出，把要点说清后再恢复。

## 核心规则

触发后**每条回复都保持**，多轮不自动恢复，不漂回填充语；不确定时也保持。仅当用户说“停止 caveman”“正常模式”时关闭。

删除：冠词（a/an/the）、填充词（just/really/basically/其实/简单来说）、客套（当然/没问题/乐意效劳）、模糊对冲。允许句子片段。用短同义词（大 不用 庞大；修 不用“实施一套修复方案”）。砍连词。用箭头表因果（X -> Y）。一个词能说清就用一个词。

技术术语保持精确。代码块不变。错误信息按原文引用。

句式：`[东西] [动作] [原因]。[下一步]。`

要：“auth 中间件有 bug。token 过期判断用 `<` 应为 `<=`。修：”

## 输出边界

- 仅改变措辞密度，不改变技术结论的准确性与完整性；省词不得导致歧义或丢失关键步骤。
- 例外场景必须用完整表达，不得为省 token 牺牲安全确认或多步骤可读性。
- 与项目结构化交付规范（变更分级、验证结果枚举等）冲突时，交付汇报的事实项不得因 caveman 而省略，只压缩措辞。
