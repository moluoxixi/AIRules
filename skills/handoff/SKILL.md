# Handoff

把当前会话压缩成一份交接文档，让一个没有本会话历史的新 agent 能接着干，而不必重读整段对话。

## 触发条件

- 用户说“交接”“接力”“写个 handoff”“总结给下一个会话/agent”“我要换窗口继续”。
- 当前上下文即将被压缩或超长，需要把关键状态落盘以免丢失。
- 一个长任务要移交给另一个 agent / 另一台机器 / 另一个时间段继续。

## 不适合场景

- 任务已经彻底完成、无后续动作时，不需要交接文档，直接给最终汇报即可。
- 只是想要一句话进度小结，而非给新 agent 的接力包时，不要套用本流程。
- 已有 PRD、实现计划、ADR、issue 等正式产物覆盖了全部待办时，优先更新那些产物，handoff 只做指针与现场状态补充。

## 输出边界

- **写入位置**：写到操作系统临时目录，不写进当前仓库工作区。优先用 `$TMPDIR`，回退 `/tmp`（Windows 用 `%TEMP%`），文件名 `handoff-<YYYYMMDD-HHMMSS>.md`，每次运行生成新文件。交付时把绝对路径告诉用户。
- **不重复已有产物**：PRD、实现计划、ADR、issue、commit、diff 里已经写清的内容，用路径或 URL 引用，不要在交接文档里复制一遍。
- **脱敏**：API key、口令、token、个人隐私信息一律不写进文档；需要引用时只写键名或来源位置，不写明文值。
- **不臆造状态**：未验证的结论、不确定的事实标记为 `MISSING` 或“待确认”，不得写成已完成。交接文档只陈述本会话真实发生过的动作与已验证的结果。

## 流程

### 1. 收集现场状态

从当前会话提取下列事实，逐项核对真实性，不靠记忆补全：

- **任务目标**：用户最初要解决什么、验收标准是什么。
- **已完成**：本会话真实改动过的文件、运行过的命令及结果（`PASS`/`FAIL`/`MISSING`/`NOT RUN`）。
- **进行中**：当前卡在哪一步、上一条命令的输出、正在调试的假设。
- **待办**：下一步该做什么，按优先级排序。
- **关键决策与约束**：已拍板的方案选择、用户明确的偏好、必须遵守的边界。
- **坑与教训**：本会话踩过的环境问题、失败路径、绕过办法。

### 2. 写交接文档

按以下结构写入临时目录文件（章节标题为固定结构，内容据实填写）：

```
# Handoff: <任务简称>

## 目标与验收
<最初目标 + 验收标准；引用 PRD/issue 路径>

## 当前状态
<进行中的具体步骤、最近一条命令输出、当前假设>

## 已完成
<改动文件清单 + 验证命令与结果状态>

## 待办（按优先级）
1. <下一步>
2. ...

## 关键决策与约束
<已拍板方案、用户偏好、边界>

## 坑与教训
<环境问题、失败路径、绕过办法>

## 建议加载的 skills
<列出新 agent 接手时应加载的 skill 名称及理由，例如调试类、实现计划类、验证类>

## 引用产物
<PRD / 实现计划 / ADR / issue / 分支 / commit 的路径或 URL，不复制内容>

## 待确认 / MISSING
<未验证或缺失的关键事实；没有则写"无">
```

> 上面的代码块是交接文档的结构模板（占位示例），尖括号内为填写说明，不是真实内容；填写时必须用本会话的真实事实替换，未确认项保留为 `MISSING`，不得直接照抄占位文字。

### 3. 交付

- 把交接文档的绝对路径告诉用户。
- 用三五句话口头小结：任务卡在哪、下一步是什么、有无 `MISSING`。
- 若用户传了参数（说明下一会话的侧重），按该侧重裁剪文档详略。

## 失败处理

- 临时目录不可写时，报告 `FAIL handoff write`，并把交接内容直接贴在回复里供用户手动保存，不静默吞掉。
- 无法确认某项状态真实性时，该项标 `MISSING` 并在交付小结中点出，不得猜测填充。
