# 后端项目文档规范

## 场景分层

- HTTP API 服务：业务接口、请求响应、错误码、分页、鉴权、Mock 和联调说明写入 `docs/api/`；全局协议只维护在 `docs/api/_protocol.md`。
- 领域服务或业务模块：业务背景、状态流转、字段口径、权限、验收标准写入 `docs/prds/`；不得只用接口实现反推需求。
- 定时任务、消息消费者、队列、事件或 Webhook：把外部可见的事件契约、重试策略、幂等键、死信处理和上下游依赖写入 `docs/api/` 或架构文档，并在 `docs/map.md` 标明类型。
- 后端库包或 SDK：对外 API、版本兼容、错误语义和使用示例写入 API 文档；内部私有函数不单独成篇。

## 架构与协议边界

- 模块边界、分层、依赖方向、数据流、部署拓扑、权限模型和技术选型写入 `docs/architecture/`。
- 影响模块边界、数据模型、接口协议、错误码体系、部署拓扑或长期演进成本的决策必须记录 ADR。
- 业务接口文档不得重复定义全局返回结构、错误结构、分页、鉴权、Headers 或版本策略；只能引用 `docs/api/_protocol.md` 或记录明确协议偏差。
- 数据库表结构不等于业务需求；字段口径、状态含义和验收标准必须落到 PRD 或 API 文档。

## 代码变更同步

- 修改路由、Controller、Resolver、DTO、OpenAPI、错误码、鉴权、分页、事件契约或外部调用时，同步更新 API 文档。
- 修改领域规则、状态机、权限、数据一致性、幂等、重试或补偿逻辑时，同步更新 PRD、测试文档或架构文档。
- 修改测试分层、Mock/fixture、联调范围、回归范围或数据准备时，同步更新 `docs/test/`。
- 纯内部重构、无对外契约变化的私有实现变更，可在交付中标记 `N/A docs` 并说明依据。
