# 项目文档知识库

## 读取顺序

- 当任务涉及架构、模块边界、需求、接口联调、测试设计、业务流程、字段口径、验收标准或用户提到具体业务域时，必须先检索并读取 `docs/`。
- 优先读取 `docs/map.md`，再读取相关目录的 `index.md`，最后按关键词读取命中的业务文档。
- 涉及架构、分层、依赖方向、部署、权限模型或技术选型时，必须读取 `docs/architecture/index.md`、`docs/architecture/overview.md` 和相关 ADR。
- 涉及接口、联调、请求封装、错误处理、分页、鉴权或 Mock 时，必须读取 `docs/api/_protocol.md` 和相关业务接口文档。
- 若相关内容未在分类目录中找到，必须读取 `docs/other/index.md`，检查是否存在待转换的旧文档来源。
- 检索关键词必须包含用户原始业务词、可能的英文名、接口路径、页面路由、实体名和领域缩写。
- 若相关文档存在，以文档为业务事实来源，再结合 CodeGraph 分析代码结构；不得只凭代码反推需求。
- 若相关文档缺失，交付中标记 `MISSING docs`，并说明已检索的关键词和路径。

## 维护规则

- 新增或修改架构、PRD、API、测试文档时，必须分别使用 `architecture-docs`、`prd-docs`、`api-docs`、`test-docs`；组件库、SDK、消息等场景专属文档按对应场景规范指定的 skill 执行，并同步更新目录 `index.md` 与 `docs/map.md`。
- 文档按业务域独立成篇；例如 `docs/prds/采购订单.md`、`docs/api/采购订单.md`、`docs/test/采购订单.md`。
- 全局接口协议维护在 `docs/api/_protocol.md`；业务接口文档不得重复定义冲突协议。
- 架构决策维护在 `docs/architecture/decisions/`，影响模块边界、技术选型、数据模型、接口协议或部署拓扑时必须记录 ADR。
- 前端、后端、组件库、SDK、任务或消息等场景差异，按对应场景规范执行；通用规则不重复描述具体场景写法。
- 初始化前已存在的旧文档归档在 `docs/other/imported/`；`docs/other/index.md` 只作为来源索引和转换状态表，不是最终业务知识库。
- 旧文档必须转换为标准分类文档后再作为业务事实长期使用；无法转换时标记 `MISSING conversion` 并说明缺失信息或冲突。
- 不得把需求、接口、测试、架构和场景专属契约混写到同一个文档；跨文档关系通过链接引用。

## 旧文档标准化

- 处理 `docs/other/imported/` 时，必须先读取来源文档全文，再结合代码事实和已分类 docs 判断归属。
- 来源文档包含需求、接口、测试、架构或项目场景文档中的多类信息时，必须拆分到对应目录，不得把混合内容原样复制到单个目标文档。
- 转换目标必须使用标准位置：PRD 写入 `docs/prds/`，接口写入 `docs/api/`，测试写入 `docs/test/`，架构写入 `docs/architecture/`；场景专属文档按场景规范写入。
- 来源文档只能作为证据引用；转换后应在目标文档 `## 来源` 中链接原始归档路径。
- 转换完成后，同步更新目标目录 `index.md`、`docs/map.md` 和 `docs/other/index.md` 的状态；不得让 `docs/other/imported/` 成为唯一可读入口。
- 发现旧文档与代码事实、用户口径或已分类 docs 冲突时，停止并报告冲突，等待确认后再转换。

## 代码变更与文档同步

- 修改代码前，若任务涉及业务行为、接口契约、架构边界、测试策略、权限、状态机、数据一致性或用户可见流程，必须先读取相关 docs。
- 修改代码过程中发现实现与 docs 不一致时，必须停止并报告冲突；不得静默让代码覆盖文档事实。
- 修改代码后，若行为、接口、架构、测试策略或场景专属契约发生变化，必须同步更新对应 docs、目录 `index.md` 和 `docs/map.md`。
- 若本次代码变更不需要更新 docs，交付中必须说明 `N/A docs` 及理由；若应更新但信息不足，标记 `MISSING docs update` 并说明缺口。

## 评审门槛

- L0 可直接执行：已有边界内的小补充、事实明确的字段或示例更新、沿用现有模式的低风险测试。
- L1 先输出变更摘要：轻微结构调整、索引或 `docs/map.md` 更新、不会改变公共契约的文档拆分。
- L2 必须先输出设计或拆分报告并等待开发者确认：架构边界、接口协议、错误码体系、分页策略、PRD 业务域拆分、组件库公共契约、SDK 对外 API、事件契约、测试策略、Mock/fixture 策略、E2E/联调范围、权限/状态机/数据一致性规则。
- 若无法判断属于哪个等级，按更高等级处理；不得用低等级绕过评审。
