# 前端项目文档规范

## 场景分层

- 普通前端应用：按业务域维护 `docs/prds/`、`docs/api/`、`docs/test/`；普通业务组件不生成独立组件文档，组件事实优先通过 CodeGraph、源码、类型和测试读取。
- 组件库或 Design System：持续维护 `docs/components/`，组件库文档由 `components-docs` 生成或更新，并同步 `docs/components/index.md` 与 `docs/map.md`。
- 管理后台或业务中台：业务流程、字段口径、权限、表格/表单联动写入 PRD；接口联调写入 API；回归范围和用例矩阵写入测试文档。
- 前端 BFF、Mock、请求封装或跨端协议：接口契约和协议偏差写入 `docs/api/`，不得散落在组件说明中。

## 组件库文档边界

- 只有对外复用、跨项目消费或作为设计系统发布的组件库才写入 `docs/components/`。
- 组件库文档的写作结构、示例、Props/Events/Slots、可访问性和变更记录由 `components-docs` 负责；本规范只定义何时需要写。
- 普通页面组件、业务私有组件、路由页面内的组合组件不写独立组件文档；如影响用户流程或验收标准，应更新 PRD 或测试文档。
- 使用第三方组件库时，优先引用官方文档、已有组件库文档或扫描其源码；不得把第三方组件 API 复制进本项目 `docs/components/`。

## 代码变更同步

- 修改用户可见流程、字段口径、权限、状态机、表单提交、列表筛选、上传、编辑器、图表或复杂交互时，先读取相关 PRD/API/测试文档。
- 修改请求参数、响应消费、错误处理、分页、鉴权或 Mock 时，同步更新 API 文档。
- 修改组件库公共契约时，同步更新组件库文档；修改普通业务组件时只在影响 PRD/API/测试事实时更新对应文档。
- 纯样式微调、内部重构、无契约变化的普通组件实现变更，可在交付中标记 `N/A docs` 并说明依据。
