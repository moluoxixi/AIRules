# Retrospective Correction

## 触发条件

- 用户指出“实现和我要求的不一致”“你理解错了”“这不是我要的”“偏了”“规则没按”等偏差。
- 用户要求分析为什么偏差发生，或判断是 AI 执行错误、skills 缺口、rules 缺口还是需求不明确。
- 已完成的代码、文档、测试、计划或规则生成结果需要先修正方向，再决定是否更新 AIRules。

## 硬性规则

- 不得立即修改代码、文档或规则。
- 先读取用户原始要求、最新反馈、当前实现、已使用的 rules/skills、相关测试和验证输出。
- 必须先输出《改动计划清单》，等待用户确认后，才能执行修复或做最终归因。
- 不得在标准未确认前归因；不得用“规则不清楚”替 AI 执行错误开脱。
- 若判断需要修改 skills 或 rules，只能先提出更新建议；未经用户确认不得直接改。
- 修复和验证完成后，必须生成独立《偏差原因分析》文档；最终回复的摘要不能替代文档。
- 原因分析必须明确判断主因是 `AI_EXECUTION_ERROR`、`SKILL_GAP`、`RULE_GAP`、`REQUIREMENT_AMBIGUITY`、`CONTEXT_LOSS` 还是 `TOOL_OR_ENVIRONMENT`，并说明为什么不是其它分类。

## 流程

1. **偏差复述**：用用户语言重述偏差点和期望结果。
2. **证据收集**：列出已读取的请求、文件、rules、skills、测试输出和实现位置。
3. **改动计划清单**：先给用户确认修复范围。
4. **标准确认**：用户确认计划后，将计划中的期望结果转成明确验收标准。
5. **原因归因草案**：基于证据形成待验证分类，不猜测、不甩锅。
6. **执行修复**：按确认后的计划修改，并运行必要验证。
7. **生成原因文档**：将确认后的标准、事实证据、根因分类、修复动作、验证结果和预防动作写入新文档。
8. **最终回复**：链接原因文档，摘要说明根因分类和验证结果。

## 原因文档输出

- 默认路径：`docs/retrospective-corrections/<YYYY-MM-DD>-<短问题名>.md`。
- 若项目没有 `docs/`，创建 `docs/retrospective-corrections/`；若用户指定路径，使用用户指定路径。
- 文档必须是本次修复新建文件，不得覆盖旧分析文档；同名冲突时改用更具体文件名。
- 若文件系统不可写，必须在最终回复标记 `FAIL retrospective document` 并输出完整文档内容；不得伪造成已写入。
- 原因文档必须在修复和验证之后生成；不得在修复前用未验证结论定稿。
- 文档中的根因分类必须给出一个主因；存在多个因素时列为次因。

## 改动计划清单格式

```md
# 改动计划清单

## 偏差点

## 期望标准

## 拟修改范围

| 项 | 文件/模块 | 修改内容 | 验证方式 | 风险 |
|---|---|---|---|---|

## 是否可能需要更新 rules/skills

## 等待确认
```

## 原因归因分类

| 分类 | 含义 |
|---|---|
| `AI_EXECUTION_ERROR` | 现有要求、rules 或 skills 已清楚表达，但 AI 没有遵守或执行遗漏。 |
| `SKILL_GAP` | 应触发的 skill 缺少必要流程、检查点、反例或输出格式。 |
| `RULE_GAP` | 项目 rules 没有覆盖该约束，或表达模糊、冲突、不可执行。 |
| `REQUIREMENT_AMBIGUITY` | 用户要求存在多个合理解释，且未提供足够验收标准。 |
| `CONTEXT_LOSS` | AI 未读取、遗漏或误用已有上下文、文档、代码或前序结论。 |
| `TOOL_OR_ENVIRONMENT` | 工具、依赖、平台、权限、缓存或外部状态导致结果偏差。 |

## 原因报告格式

```md
# 偏差原因分析

## 确认后的标准

## 事实证据

## 根因分类

- 主因：
- 次因：

## 为什么不是其它分类

## 修复动作

## 验证结果

## 预防动作
```

## 示例

```md
# 偏差原因分析

## 确认后的标准

`init-project` 遇到已有 `AGENTS.md` 时，不应注入 DIY 占位段。

## 事实证据

- 用户反馈：已有 `AGENTS.md` 需要保留。
- 当前脚本：无论文件是否存在，都注入 `airules-base.md`。
- 现有 rules：未明确区分新建与已有 `AGENTS.md`。

## 根因分类

- 主因：`RULE_GAP`
- 次因：无

## 为什么不是其它分类

不是单纯 `AI_EXECUTION_ERROR`，因为原规则没有明确要求“已有 AGENTS.md 时跳过 base 占位”。

## 修复动作

- 修改脚本，已有非空 `AGENTS.md` 时跳过 `airules-base.md`。
- 补充测试。

## 验证结果

- `npx vitest run tests/init-project-scripts.test.ts`：PASS

## 预防动作

- 在 `init-project` skill 中写明新建与已有文件的差异化处理。
```
