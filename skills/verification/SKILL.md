# 完成前验证

声明完成前的证据门：实际运行、读取输出、按枚举状态收口。这是收益最高的门禁——LLM 系统性高估自己产物，运行结果是唯一可信的锚。

## 触发条件

- 准备声明任务完成、已修复或已通过
- 高风险改动（删除、生产、安全、权限、跨模块）收口前

## 不适合场景

- 仍在实现中途、尚未到收口节点
- 纯文档/注释/格式改动且无可运行验证项 → 标 `N/A` 并说明

## 验证流程

1. **识别**：列出本次改动应运行的验证项（build、test、lint、相关用例）。优先项目既有脚本与配置。
2. **运行**：实际执行命令，不跳过、不假设。
3. **读取**：读命令的真实输出，确认通过/失败的具体内容。
4. **收口**：按枚举状态记录每一项。

## 状态枚举

只能用 `PASS`、`FAIL`、`MISSING`、`NOT RUN`、`N/A`：

- 脚本/配置/依赖/测试入口缺失 → `MISSING` 或 `NOT RUN` + 原因
- 不得把失败、缺失、不相关或未运行转写成通过

## 输出边界

- 未实际运行并读取输出前，不得声明完成、已修复或已通过。
- 交付汇报精简收口：改了什么、验证命令与结果状态、未执行项及原因（没有则显式写"无"）。
- 覆盖率不足只能补有效测试或说明原因；不得降阈值、排除关键文件、删断言。
