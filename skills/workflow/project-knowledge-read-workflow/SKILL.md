# 项目知识读取工作流

## 用途

本 Skill 在开发任务、需求分析或代码审查开始前使用。它只负责按当前意图读取已有 `docs/AI项目知识/`，不记录任务状态，不创建知识库，不刷新知识库。

若 `docs/AI项目知识/项目概览.md` 或 `docs/AI项目知识/总索引.md` 不存在，项目知识读取状态为 `MISSING`。继续工作时只能依赖用户指令、源码、测试、配置和运行事实，不得假装已读取项目知识。

## 标准目录结构

```text
docs/AI项目知识/
  .state/
    knowledge-state.json
  项目概览.md
  总索引.md
  需求文档/
    索引.md
  接口文档/
    索引.md
  组件库/
    索引.md
  测试规范/
    索引.md
  项目规范/
    索引.md
  部署与运维/
    索引.md
  待确认/
    YYYY-MM-DD-commit-知识变更候选.md
```

`需求文档/`、`接口文档/`、`组件库/`、`测试规范/` 和 `项目规范/` 是只读导入目录，可由 Git 子模块提供；本 Skill 只读取已有 `索引.md` 和用户明确要求的目标文件。目录或索引缺失时报告 `MISSING`，不得创建、改写或补全文档。

## 智能上下文推断

读取项目知识前，必须先根据用户 Prompt、已知源码路径或报错位置判定读取边界。禁止无目标扫描整个知识目录。

### 场景判定与路由矩阵

1. **接口联调**：出现对接、联调、接口跑通、字段不匹配时，读 `接口文档/索引.md`，再读取接口客户端、生成类型或相关页面数据模型源码；若缺少接口文档入口，报告 `MISSING`，严禁在项目知识中补写接口参考正文。
2. **新需求开发**：出现新增功能、开发页面、业务规则、按需求实现时，读 `需求文档/索引.md` 和 `项目规范/索引.md` 定位业务入口、术语和目录边界；若任务依赖 PRD 或验收标准但当前上下文未提供，报告 `MISSING`，严禁猜测需求正文。
3. **UI/交互调整**：出现样式、间距、颜色、排版、组件替换时，读 `组件库/索引.md`、`项目规范/索引.md` 和当前业务入口源码；只在命中项目内约束时读取项目规范原子文件，严禁在项目知识中补写组件库手册。
4. **测试调整**：出现测试、用例、覆盖率、E2E、mock 或质量门时，读 `测试规范/索引.md` 和相关测试配置；若索引未命中，回到项目脚本、测试配置和现有测试事实。
5. **Bug 排查**：出现报错、没反应、生命周期异常、白屏时，优先读取报错日志、源码和相关测试；只在命中已知问题时读取 `部署与运维/索引.md`，严禁读取无关页面业务规则。
6. **代码审查**：针对变更文件读取对应领域 `索引.md` 和最多 3 个项目规范、测试规范、运维或决策原子文件；若变更只涉及技术重构，优先读取项目规范和测试规范。

若无法归类，仅读取 `项目概览.md`、`总索引.md`，再根据源码路径或用户关键词读取一个领域 `索引.md`。仍不命中时回到源码事实，不扩展读取范围。

## 项目概览与两级索引契约

`项目概览.md` 只承载路由级信息：项目一句话定位、主要技术栈、主要知识域入口和可证明的入口判断线索。长篇解释必须下沉到领域原子文件。

业务入口不得靠固定目录名推断。AI 必须根据当前仓库的路由配置、页面文件、可执行入口、导航关系、测试指针和用户任务上下文判断业务入口；无法证明时回到源码继续定位，不得把任何框架惯例目录写成默认事实。

本项目采用两级索引架构：

1. `总索引.md` 仅负责路由到各领域索引，不直接挂载原子文件。
2. 领域 `索引.md` 负责承载本领域内到具体原子文件的路由。

```markdown
| 关键词 | 读取场景 | 目标文件 | 来源证据 |
|---|---|---|---|
| 订单筛选 | 订单列表查询与分页约定 | `项目规范/订单筛选.md` | 路由配置、页面文件或测试指针 |
```

读取已存在的原子文件时，文件必须聚焦单个项目规范、工程约定、业务术语、目录边界、质量门、决策或运维知识，并在文件头部包含 frontmatter：

```markdown
---
id: "order-list-filter"
domain: "项目规范"
keywords: ["订单列表", "筛选", "分页"]
source_paths: ["实际源码路径"]
last_verified_commit: "abc123"
---
```

PRD 正文、接口参考正文和组件库手册正文不得作为项目知识原子文件；项目知识只读取它们的现有入口、项目内引用关系和可由仓库事实证明的落地约束。

`需求文档/`、`接口文档/`、`组件库/`、`测试规范/` 和 `项目规范/` 默认只读取 `索引.md`。若用户明确提供正文文件路径，只能按任务目标读取必要片段，不得复制正文或改写目录内容。

`待确认/` 中的候选文件不得被 `总索引.md` 或领域 `索引.md` 路由；只有确认沉淀后的原子知识文件才能进入正式索引。

## 注入控制

- 优先读取 `项目概览.md`、`总索引.md`，再下钻到单个领域 `索引.md`。
- 默认不一次读取超过 3 个原子知识文件；若命中超过 3 个，必须先说明命中原因并缩小范围。
- 禁止无目标扫描整个项目知识目录，禁止一次注入整个领域目录。
- 若索引未命中，需回到源码、路由配置或接口定义中直接定位事实，禁止擅自猜测补全上下文。
- `待确认/` 只在用户明确要求审查候选知识时读取，常规开发任务不得读取。

## 入口与映射边界

`项目规范/索引.md` 中的业务模块必须受控于当前仓库事实。只有可由路由配置、页面文件、可执行入口、导航关系、测试指针或用户任务上下文证明的具体页面、路由入口或用户可达业务入口，才能被定义为业务模块。禁止把业务模块主路径指向抽象架构层、通用 UI 组件库、hooks、stores、services 或 utils。

`需求文档/索引.md`、`接口文档/索引.md` 和 `组件库/索引.md` 只记录已有入口的路径、链接、适用场景、关键词和最近核对证据。接口索引可记录接口路径、调用位置、客户端文件和生成类型；组件库索引可记录组件导入、使用页面和测试指针。禁止摘抄、改写或总结长篇正文；正文缺失时只能报告 `MISSING`，不得用项目知识补全。
