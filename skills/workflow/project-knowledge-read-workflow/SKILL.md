# 项目知识读取工作流

## 用途

本 Skill 必须在开发任务、需求分析或代码审查开始前触发。它只负责通过轻量索引按需读取 `docs/AI项目知识/` 中的项目概览、需求、设计、接口、质量、交付、运行和生成索引，不记录任务状态，也不刷新知识库。任务完成后的知识刷新使用 `project-knowledge-refresh-workflow`。

## 项目概览.md 契约

`项目概览.md` 必须短小，负责路由而不是承载长知识：

- 项目一句话定位、主要技术栈、业务模块根目录和主要接口形态。
- 本项目上下文读取顺序，以及需求、设计、接口、质量、交付、运行各目录的适用边界。
- 指向当前项目最常用的需求、设计、接口、生成索引或决策记录路径。

长篇需求、架构、领域模型、接口契约、命令细节、测试矩阵、发布流程和运维信息必须拆成原子文件，并通过 `索引/` 路由，不要塞进 `项目概览.md`。

## 索引文件契约

索引文件只负责定位，不承载长内容。每条索引必须说明关键词、读取条件、目标文件和事实来源：

```markdown
| 关键词 | 何时读取 | 文件 | 覆盖范围 | 来源 |
|---|---|---|---|---|
| 订单筛选 | 涉及订单列表查询、筛选、分页 | `需求/用户场景/订单列表筛选.md` | 订单列表页 | `src/views/order/list` |
```

索引文件应短小、稳定、可扫描。`总索引.md` 只路由到领域索引；领域索引只路由到原子知识文件；原子知识文件再给出具体背景、约束和证据路径。

原子知识文件建议包含 frontmatter，便于 AI 快速判断是否读取：

```markdown
---
id: "order-list-filter"
domain: "需求"
keywords: ["订单列表", "筛选", "分页"]
source_paths: ["src/views/order/list"]
last_verified_commit: "abc123"
---
```

## Lazy Loading

默认读取顺序：

1. 用户本次明确指令与当前宿主规则。
2. `docs/AI项目知识/项目概览.md`。
3. `docs/AI项目知识/索引/总索引.md`。
4. 按任务关键词、业务模块、路径或接口名读取一个或少数几个领域索引。
5. 只读取领域索引命中的原子知识文件。
6. 当前任务相关源码、测试、manifest 和 CI 配置。
7. 必要时按源码证据回查特定知识文件。

禁止无目标扫描整个项目知识目录，禁止一次注入整个领域目录。索引是导航入口，不是替代源码、测试、接口契约和运行配置验证的事实来源。

## 注入控制

- 先读 `项目概览.md` 和必要索引，再读原子文件。
- 默认不一次读取超过 3 个原子知识文件；超过时先总结命中原因并缩小范围。
- 不读取与当前任务关键词、路径、接口、模块无关的知识文件。
- 若索引命中不足，回到源码、路由、接口定义和测试中定位事实，不用猜测补全知识库。

## 业务模块映射

`生成索引/业务模块映射.md` 必须映射到项目业务模块目录下的具体页面或用户入口。业务模块根目录按项目识别，不固定为 `views`，可为 `src/views`、`src/pages`、`app`、`features`、`modules` 等。

禁止把业务模块主路径指向抽象架构层、通用 UI 组件库、hooks、stores、services、utils、shared 或底层 lib。通用组件或服务只能出现在依赖说明中。

推荐格式：

```markdown
| 业务模块 | 具体页面/入口路径 | 用户界面 | 业务职责 | 相关测试 | 依赖说明 |
|---|---|---|---|---|---|
| 订单列表 | `src/views/order/list` | 订单列表页 | 查询、筛选、批量操作 | `src/views/order/list/*.spec.ts` | 依赖订单 API |
```
