# 项目知识读取工作流

## 用途

本 Skill 在开发任务、需求分析或代码审查开始前使用。它只负责按当前意图读取已有 `docs/AI项目知识/`，不记录任务状态，不创建知识库，不刷新知识库。

若 `docs/AI项目知识/项目概览.md` 或 `docs/AI项目知识/总索引.md` 不存在，项目知识读取状态为 `MISSING`。继续工作时只能依赖用户指令、源码、测试、配置和运行事实，不得假装已读取项目知识。

## 智能上下文推断

读取项目知识前，必须先根据用户 Prompt、已知源码路径或报错位置判定读取边界。禁止无目标扫描整个知识目录。

### 场景判定与路由矩阵

1. **接口联调**：出现对接、联调、接口跑通、字段不匹配时，读 `架构映射/API映射清单.md`，再读取目标接口原子文件、数据契约和相关页面数据模型；严禁读取宏观需求、全局架构和部署流程。
2. **新需求开发**：出现新增功能、开发页面、业务规则、按需求实现时，读 `架构映射/业务模块映射.md` 定位业务入口，再读取命中的需求、业务规则或数据模型原子文件；未进入联调前不读详细接口契约。
3. **UI/交互调整**：出现样式、间距、颜色、排版、组件替换时，读 `架构映射/组件使用映射.md` 和当前业务入口源码；只在组件行为不明时读取 `组件与交互/` 原子文件，严禁读取后端 API、数据库模型和全局业务规划。
4. **Bug 排查**：出现报错、没反应、生命周期异常、白屏时，优先读取报错日志、源码和相关测试；只在命中已知问题时读取 `部署与运维/已知问题排查.md`，严禁读取无关页面业务规则。
5. **代码审查**：针对变更文件读取对应领域 `索引.md` 和最多 3 个原子文件；若变更只涉及技术重构，优先读取架构映射和测试映射。

若无法归类，仅读取 `项目概览.md`、`总索引.md`，再根据源码路径或用户关键词读取一个领域 `索引.md`。仍不命中时回到源码事实，不扩展读取范围。

## 项目概览与两级索引契约

`项目概览.md` 只承载路由级信息：项目一句话定位、主要技术栈、业务入口根目录、主要知识域入口。长篇解释必须下沉到领域原子文件。

```markdown
## 业务入口根目录

- `src/views`
- `src/pages`
```

本项目采用两级索引架构：

1. `总索引.md` 仅负责路由到各领域索引，不直接挂载原子文件。
2. 领域 `索引.md` 负责承载本领域内到具体原子文件的路由。

```markdown
| 关键词 | 读取场景 | 目标文件 | 来源证据 |
|---|---|---|---|
| 订单筛选 | 订单列表查询与分页 | `需求与设计/业务规则/订单列表筛选.md` | 项目概览声明的入口路径 |
```

原子文件必须聚焦单个需求、规则、接口、组件约束、数据模型、决策或运维知识，并在文件头部包含 frontmatter：

```markdown
---
id: "order-list-filter"
domain: "需求与设计"
keywords: ["订单列表", "筛选", "分页"]
source_paths: ["src/views/order/list"]
last_verified_commit: "abc123"
---
```

`待确认/` 中的候选文件不得被 `总索引.md` 或领域 `索引.md` 路由；只有确认沉淀后的原子知识文件才能进入正式索引。

## 注入控制

- 优先读取 `项目概览.md`、`总索引.md`，再下钻到单个领域 `索引.md`。
- 默认不一次读取超过 3 个原子知识文件；若命中超过 3 个，必须先说明命中原因并缩小范围。
- 禁止无目标扫描整个项目知识目录，禁止一次注入整个领域目录。
- 若索引未命中，需回到源码、路由配置或接口定义中直接定位事实，禁止擅自猜测补全上下文。
- `待确认/` 只在用户明确要求审查候选知识时读取，常规开发任务不得读取。

## 业务模块映射边界

`架构映射/业务模块映射.md` 必须受控于 `项目概览.md` 声明的业务入口根目录。只有该根目录下的具体页面、路由入口或用户可达业务入口，才能被定义为业务模块。

禁止把业务模块主路径指向抽象架构层、通用 UI 组件库、hooks、stores、services 或 utils。通用组件只能作为依赖项出现在说明中。
