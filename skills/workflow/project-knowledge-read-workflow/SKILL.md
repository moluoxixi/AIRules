# 项目知识读取工作流

## 用途

本 Skill 必须在开发任务、需求分析或代码审查开始前触发。它负责根据当前任务场景，通过轻量推断按需读取 `docs/AI项目知识/` 中的特定知识域，防范上下文超载（Context Bloat）。它不记录任务状态，不刷新知识库。任务完成后的知识刷新使用 `project-knowledge-refresh-workflow`。

## 智能上下文推断

Agent 在执行任何项目知识文件读取操作前，必须先对用户 Prompt 进行意图分析。严禁在未确立阅读边界前盲目扫盘。

### 场景判定与路由矩阵

1. **接口联调**：出现对接、联调、接口跑通、字段不匹配时，直达 `架构映射/API映射清单.md` 定位目标接口文件，仅读取该接口的原子文件及目标页面的数据模型；严禁读取宏观需求、系统架构和部署流程。
2. **新需求开发**：出现新增功能、开发页面、业务规则、按需求实现时，读 `架构映射/业务模块映射.md` 定位业务路径，再读取对应的 `需求与设计/业务规则/`；严禁读取详细接口契约，除非进入实质联调。
3. **UI/交互调整**：出现样式、间距、颜色、排版时，仅依赖当前业务层源码和公共 UI 组件；严禁读取后端 API、数据库模型和全局业务规划。
4. **Bug 排查**：出现报错、没反应、生命周期异常、白屏时，读取当前报错日志、源码，并按需读取 `部署与运维/已知问题排查.md`；严禁读取全局架构和无关页面业务规则。

若无法归类，仅读取 `项目概览.md`、`总索引.md`，再根据源码路径或用户关键词读取一个领域 `索引.md`。仍不命中时回到源码事实，不扩展读取范围。

## 项目概览与两级索引契约

`项目概览.md` 提供一句话定位、主要技术栈，并且必须声明本项目的业务入口根目录：

```markdown
## 业务入口根目录

- `src/views`
```

本项目采用两级索引架构：

1. `总索引.md` 仅负责路由到各领域索引，不直接挂载原子文件。
2. 领域 `索引.md` 负责承载本领域内到具体原子文件的路由。

```markdown
| 关键词 | 读取场景 | 目标文件 | 来源证据 |
|---|---|---|---|
| 订单筛选 | 订单列表查询与分页 | `需求与设计/业务规则/订单列表筛选.md` | 项目概览声明的入口路径 |
```

长篇知识必须拆成原子文件，并在文件头部包含供机器快速识别的 frontmatter：

```markdown
---
id: "order-list-filter"
domain: "需求与设计"
keywords: ["订单列表", "筛选", "分页"]
source_paths: ["src/views/order/list"]
last_verified_commit: "abc123"
---
```

`待确认/` 中的候选文件不得被 `总索引.md` 或领域 `索引.md` 路由；只有确认沉淀后的原子知识文件才能进入正式索引。

## 注入控制

- 优先读取 `项目概览.md`、`总索引.md`，再下钻至单个领域的 `索引.md`。
- 默认不一次读取超过 3 个原子知识文件；若超出，Agent 必须先总结命中原因并缩小范围。
- 禁止无目标扫描整个项目知识目录，禁止一次注入整个领域目录。
- 若索引未命中，需回到源码、路由配置或接口定义中直接定位事实，禁止擅自猜测补全上下文。
- `待确认/` 只在用户明确要求审查候选知识时读取，常规开发任务不得读取。

## 业务模块映射边界

`架构映射/业务模块映射.md` 必须受控于 `项目概览.md` 中声明的业务入口根目录。只有在该目录下登记的具体页面或入口，才能被定义为业务模块。

禁止把业务模块主路径指向抽象架构层、通用 UI 组件库、hooks、stores、services 或 utils。通用组件只能作为依赖项出现在说明中。
