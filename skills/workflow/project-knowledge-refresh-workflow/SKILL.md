# 项目知识刷新工作流

## 用途

本 Skill 处理任务完成后的知识刷新。它不记录任务状态，不定义宿主触发机制，仅按 commit 范围刷新 `docs/AI项目知识/` 以保证知识的延续性。

调用方负责在任务完成后触发本 Skill。若本 Skill 没有被触发，交付报告必须把知识刷新标为 `NOT RUN`，并说明缺少触发结果。

## 推荐目录结构

本 Skill 强依赖并维护以下精简且包含两级索引的目录结构：

```text
docs/AI项目知识/
  .state/
    knowledge-state.json
  项目概览.md
  总索引.md
  需求与设计/
    索引.md
  接口与依赖/
    索引.md
  架构映射/
    索引.md
    业务模块映射.md
    技术栈.md
    命令清单.md
    测试映射.md
    API映射清单.md
  部署与运维/
    索引.md
  待确认/
    YYYY-MM-DD-commit-知识变更候选.md
```

`knowledge-state.json` 记录已沉淀到知识库的 commit 边界：

```json
{
  "last_refresh_commit": "abc123",
  "last_refresh_at": "2026-05-29T00:00:00+08:00",
  "generator_version": "project-knowledge-v2-neutral"
}
```

## 触发规则

以下场景必须执行知识刷新检查：

- 开发任务完成且必要验证已结束。
- 用户明确要求“更新知识库”“刷新项目知识”“同步文档”。

知识刷新检查必须真实执行或显式报告 `NOT RUN` / `MISSING`，不得伪造成已完成。

## 刷新边界与操作流

默认只处理 committed changes。未提交的工作树属于 WIP，严禁直接沉淀为长期知识。

推荐流程：

1. 读取 `docs/AI项目知识/.state/knowledge-state.json`。
2. 取得 `last_refresh_commit..HEAD` 的 commit 和变更文件。
3. 若存在 dirty working tree，知识刷新状态必须输出为 `NOT RUN`，并在报告中说明原因为 `dirty working tree present`，立即停止任何索引或文件的覆盖写入。
4. 根据 committed changes 自动更新 `总索引.md`、各领域 `索引.md` 和 `架构映射/` 目录下的清单。
5. 对 `需求与设计/`、`接口与依赖/`、`部署与运维/` 生成 `待确认/` 候选更新，除非用户明确允许直接改写。
6. 刷新成功后更新 `knowledge-state.json`。
7. 输出 PASS/FAIL/MISSING/NOT RUN 状态。

## 自动改写与候选阻断边界

允许 Agent 自动写入更新的目录与文件：

- `总索引.md`
- 各领域下的 `索引.md`
- `架构映射/业务模块映射.md`
- `架构映射/技术栈.md`
- `架构映射/命令清单.md`
- `架构映射/测试映射.md`
- `架构映射/API映射清单.md`

拦截并转入候选池 `待确认/` 的目录：

- `需求与设计/` 内部文件
- `接口与依赖/` 内部文件
- `部署与运维/` 内部文件

长篇、具有业务解释性的抽象知识必须生成候选文件。候选文件必须包含来源 commit、路径、变更摘要、建议落点和置信度。`待确认/` 中的候选文件不得被 `总索引.md` 或领域 `索引.md` 路由；只有确认沉淀后的原子知识文件才能进入正式索引。新增、拆分或删除原子知识文件时，必须同步更新对应的领域 `索引.md`。

## 映射文件与原子知识边界

- **API 映射清单 vs 接口原子文件**：`架构映射/API映射清单.md` 仅作为查阅入口，只允许记录路由路径和目标文件指针。具体的接口字段、请求/响应数据结构、外部依赖详情，必须存入 `接口与依赖/` 目录下具体的原子文件中，严禁污染映射清单。
- **业务模块约束**：刷新 `架构映射/业务模块映射.md` 时，模块的主体路径必须受控于 `项目概览.md` 中声明的业务入口根目录。

## 交付报告状态

知识刷新报告必须且仅使用以下状态结尾：

- `PASS`：刷新已执行，映射与索引已更新，抽象知识变更已存入 `待确认/`，状态文件已更新。
- `FAIL`：刷新执行失败，暴露底层错误栈。
- `MISSING`：项目缺少 `docs/AI项目知识/`、Git 信息或必要刷新入口。
- `NOT RUN`：遇到 dirty working tree、宿主未触发，或用户主动拦截。
- `N/A`：本次任务的 commit 评估未产生实质性的系统架构或项目知识变动。
