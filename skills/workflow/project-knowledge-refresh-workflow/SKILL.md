# 项目知识刷新工作流

## 用途

本 Skill 处理任务完成后的知识刷新。它不记录任务状态，不创建任务状态目录，不定义宿主触发机制，只按 commit 范围刷新 `docs/AI项目知识/`。

调用方负责在任务完成后触发本 Skill。若本 Skill 没有被触发，交付报告必须把知识刷新标为 `NOT RUN`，并说明缺少触发结果。


`knowledge-state.json` 记录已沉淀到知识库的 commit 边界：

```json
{
  "last_refresh_commit": "abc123",
  "last_refresh_at": "2026-05-29T00:00:00+08:00",
  "generator_version": "project-knowledge-v1"
}
```

## 触发规则

以下场景必须执行知识刷新检查：

- 开发任务完成且必要验证已结束。
- 用户明确要求“更新知识库”“刷新项目知识”“同步文档”。

知识刷新检查必须真实执行或显式报告 `NOT RUN` / `MISSING`，不得伪造成已完成。

## 刷新边界

默认只处理 committed changes。未提交工作树属于 WIP，不得直接沉淀为长期知识。

推荐流程：

1. 读取 `docs/AI项目知识/.state/knowledge-state.json`。
2. 取得 `last_refresh_commit..HEAD` 的 commit 和变更文件。
3. 若存在 dirty working tree，只报告 WIP 风险，不把未提交内容写入长期知识。
4. 根据 committed changes 更新 `索引/` 和 `生成索引/`。
5. 对 `需求/`、`设计/`、`接口/`、`质量/`、`交付/`、`运行/` 生成 `待确认/` 候选更新，除非用户明确允许直接改写。
6. 刷新成功后更新 `knowledge-state.json`。
7. 输出 PASS/FAIL/MISSING/NOT RUN 状态。

首次运行缺少 `knowledge-state.json` 时，以当前 `HEAD` 建立初始状态；若需要回填历史，必须由用户明确指定 commit 范围。

## 自动与候选边界

可以自动更新：

- `索引/总索引.md`
- `索引/需求索引.md`
- `索引/设计索引.md`
- `索引/接口索引.md`
- `索引/质量索引.md`
- `索引/交付索引.md`
- `索引/运行索引.md`
- `索引/业务模块索引.md`
- `生成索引/业务模块映射.md`
- `生成索引/技术栈.md`
- `生成索引/命令清单.md`
- `生成索引/测试映射.md`
- `生成索引/API映射.md`

默认不直接覆盖：

- `需求/`
- `设计/`
- `接口/`
- `质量/`
- `交付/`
- `运行/`

这些抽象知识需要生成候选文件，候选文件必须包含来源 commit、来源路径、变更摘要、建议落点和置信度。用户明确要求自动沉淀时，仍必须保留来源 commit 和路径证据。

索引更新必须先于候选知识更新。新增、拆分或删除原子知识文件时，必须同步更新对应领域索引，避免 AI 只能通过整目录扫描发现知识。

## 业务模块映射刷新

刷新 `业务模块映射.md` 时，必须映射到项目业务模块目录下的具体页面或用户入口。禁止把主路径指向抽象架构层、通用 UI 组件库、hooks、stores、services、utils、shared 或底层 lib。

如果变更只影响通用组件或服务，不得把它们提升为业务模块；只能在受影响业务模块的依赖说明中记录。

## 交付报告

知识刷新报告使用以下状态：

- `PASS`：刷新已执行，生成索引或候选更新已写入，状态文件已更新。
- `FAIL`：刷新执行失败，必须暴露真实错误。
- `MISSING`：项目缺少 `docs/AI项目知识/`、Git 信息或必要刷新入口。
- `NOT RUN`：当前宿主没有触发刷新，或用户明确禁止执行。
- `N/A`：本次任务未产生稳定项目知识变化。

报告中必须说明处理的 commit 范围和是否存在 dirty working tree。
