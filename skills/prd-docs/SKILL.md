# PRD Docs

## 触发条件

- 用户要求生成、更新或标准化业务需求文档、业务流程、字段口径、验收标准或需求变更时使用。
- PRD 需要与架构、API、组件或测试文档建立导航关系时使用。

## 不适合场景

- 只需要从代码推断实现细节，或用户没有确认业务规则时不要使用。
- 跨业务域拆分、合并或调整口径时，不要直接写定稿；先输出报告等待确认。

## 输出边界

- 只写 `docs/prds/`、`docs/prds/index.md` 和 `docs/map.md`。
- 不修改代码、接口协议、测试策略或其它正式文档的事实口径。

## 输出位置

- 文档路径：`docs/prds/<业务域>.md`
- 索引路径：`docs/prds/index.md`
- 地图路径：`docs/map.md`

## 写作规则

- 先读取 `docs/map.md`、`docs/prds/index.md`、相关架构文档、API 文档和同业务域已有文档；已有事实必须保留并合并。
- 只写已确认需求；缺失内容标记为 `MISSING`，不得从代码或接口猜业务规则。
- 每个业务域独立成篇；跨业务关系使用链接引用，不把多个业务域混写到同一文档。
- 新增、合并、拆分业务域，或调整业务流程、字段口径、验收标准、权限/状态机/数据一致性规则时，属于 L2，必须先输出《需求拆分与口径报告》并等待开发者确认。
- 仅在既有业务域内补充已确认字段、示例或变更记录时，可按 L0 直接更新。
- 更新或新增文档后，同步更新 `docs/prds/index.md` 和 `docs/map.md`；`docs/map.md` 必须维护业务域到 PRD/API/组件/测试文档的导航关系。

## 示例

以下内容是示例模板，仅供参考，不得作为真实业务事实自动应用。

```md
# 采购订单需求文档

## 背景

采购团队需要统一查看采购订单的创建、审批、入库与关闭状态。

## 目标

- 支持按供应商、订单状态、创建时间检索采购订单。
- 支持进入订单详情页查看明细、审批记录和入库记录。

## 字段口径

| 字段 | 含义 | 来源 | 规则 |
|---|---|---|---|
| 订单状态 | 采购订单当前生命周期 | 后端订单状态字段 | `draft` 草稿，`approved` 已审批，`closed` 已关闭 |

## 验收标准

- 输入供应商名称后，列表只展示匹配供应商的采购订单。
- 订单进入 `closed` 后，不允许继续发起审批。

## 风险与待确认

- MISSING：是否支持跨组织查看采购订单。
```
