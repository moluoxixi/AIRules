# 技术设计

## 设计目标

在保持迁移脚本现有单文件、同步执行模型的前提下，将目标清理从“仅保留 `.git`”改为经过安全校验的可配置保留计划，并将 README 处理从模板生成改为与正文无关的 Markdown 章节删除。

## 目标保留计划

### CLI 契约

- `--preserve <relative-path>` 可重复传入。
- 默认保留根 `.git` 与根 `node_modules`。
- 参数采用 POSIX 相对路径表示，拒绝空值、NUL、反斜杠、绝对路径、盘符、空路径段、`.` 与 `..`。
- 比较规则与现有重命名冲突一致：Windows 不区分大小写，其他平台区分大小写。
- 重复项去重；父项已保留时移除冗余子项。

### 安全与冲突校验

`main()` 在打印摘要和执行 `cleanTarget()` 前建立保留计划：

1. 校验每个保留路径都位于目标根内。
2. 逐段检查目标现存路径；中间路径为符号链接时拒绝，叶子符号链接作为不解引用的完整保留项。
3. 将源树经过名称替换后的输出路径加入迁移输出计划。
4. 保留根与迁移输出、Trellis 删除目标、文档转换目标存在祖先或后代重叠时拒绝。

根 `.git` 和 `node_modules` 不会由源复制计划产生，因此默认项不冲突。冲突必须在任何目标写入前报错。

### 清理算法

递归遍历目标：

- 当前路径等于保留根时停止递归并完整保留。
- 当前路径是某个保留根的祖先时继续向下，仅删除未覆盖的兄弟项。
- 其他路径递归删除。

该算法允许 `--preserve cache/downloads`，同时删除 `cache` 下未保留的旧内容。

## README 转换

### 文件选择

只处理源仓库根目录中名称匹配 `README*.md`（大小写不敏感）的常规文件。迁移预检阶段对这些文件执行严格 UTF-8 解码，确保错误发生在目标清理前。

### 章节识别

按保留原始行尾的行片段扫描：

- 维护 CommonMark fenced code block 状态；围栏允许最多三个前导空格、至少三个反引号或波浪号，关闭围栏必须使用相同字符且长度不短于开启围栏。
- 仅在围栏外识别 ATX 标题。
- Trellis 目标标题是 H2，正文忽略大小写，支持 `trellis` 或一对反引号包裹的 `` `trellis` ``，并支持 ATX closing hashes。
- 删除从目标 H2 起至下一个围栏外 H1/H2 之前的原始字符串范围；H3 及更深标题属于当前角色章节。
- 支持一个文件中多个 Trellis H2 区块。

通过对原字符串做范围切片而非重新拼接全部行，未删除区域的 LF/CRLF、空白和 UTF-8 BOM 保持不变。已有 `replaceProjectText()` 继续负责项目名与仓库链接替换。

## 其他文档与残留检查

- 删除 `regenerateReadmes()`，不再覆盖 `README.md`、`README-en.md`、`SKILLS_ORGANIZATION.md`，也不再删除 `README-zh.md`。
- `SKILLS_ORGANIZATION.md` 纳入现有定点 Trellis 清理，移除其 Trellis 角色树条目和直接判断文案，同时保留其他未知内容。
- `findTrellisResiduals()` 接收忽略根集合，跳过 `.git`、所有实际保留路径以及根 `README*.md`。README 的正确性由章节级测试保证，而不是全文件关键字禁令。

## 兼容性

- 不新增运行时依赖。
- 不改变名称替换、仓库链接替换、源排除项、`.env.local` 或现有安全校验。
- `migrationSummary()` 增加保留路径列表；帮助文本说明默认项和重复参数。
- staging 与事务回滚留待后续任务。

## 风险与控制

- 手写 Markdown 状态机可能错误识别围栏或标题：用代码围栏、closing hashes、多个区块、H1/H2 边界和 BOM/CRLF 测试约束。
- 保留目录可能掩盖迁移输出：输出计划双向祖先冲突校验并保证清理前失败。
- 嵌套保留可能经符号链接逃逸：拒绝中间符号链接，叶符号链接不解引用。
